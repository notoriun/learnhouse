Faça Você Mesmo

Esta é a construção completa. Ao final você terá um app Next.js que navega pelos seus cursos, reproduz seu conteúdo, autentica alunos, os matricula, e rastreia progresso — tudo em cima da API do Notoriun.

Está dividido em duas partes. A Parte 1 é completamente anônima — sem login, sem tokens, só leituras públicas — e te dá um site público funcionando. A Parte 2 adiciona autenticação por cima sem reescrever nada da Parte 1.

Pré-requisitos (da visão geral): Node 18+, uma instância do Notoriun em execução em http://localhost:1338, seu slug de organização, e ao menos um curso público e publicado com conteúdo. Tudo lê a base da API de uma única variável de ambiente, então ajuste se sua instância está em outro lugar.

Parte 1 — Um site de aprendizado público (sem autenticação)

Passo 1 — Estruture o app

Crie um novo app Next.js com o App Router, TypeScript, e Tailwind:

npx create-next-app@latest my-learning-platform \
  --typescript --app --tailwind --eslint --src-dir --use-npm
cd my-learning-platform

Adicione um .env.local com a base da sua API e o slug da organização. Ambos são seguros para expor ao navegador (o slug da organização é público e as leituras são anônimas), então os prefixamos com NEXT_PUBLIC_:

.env.local
NEXT_PUBLIC_LEARNHOUSE_API_URL=http://localhost:1338/api/v1
NEXT_PUBLIC_LEARNHOUSE_ORG_SLUG=your-org-slug

Substitua your-org-slug pelo seu slug real. Você pode confirmar que ele resolve abrindo http://localhost:1338/api/v1/orgs/slug/your-org-slug no seu navegador — você deve receber o JSON da organização de volta.

Passo 2 — Um pequeno cliente de API

Toda chamada ao Notoriun passa por um pequeno helper. Crie src/lib/learnhouse.ts. Isso espelha o padrão que o frontend oficial usa em apps/web/services/utils/ts/requests.ts — um wrapper fino de fetch que expõe o formato de erro { "detail": "..." } da API.

src/lib/learnhouse.ts
export const API_URL = process.env.NEXT_PUBLIC_LEARNHOUSE_API_URL!
export const ORG_SLUG = process.env.NEXT_PUBLIC_LEARNHOUSE_ORG_SLUG!
 
/**
 * Busca JSON da API do Notoriun.
 * Passe um token de acesso para autenticar (Parte 2); omita-o para leituras públicas.
 */
export async function lhFetch<T = any>(
  path: string,
  { token, ...init }: RequestInit & { token?: string } = {}
): Promise<T> {
  const res = await fetch(`${API_URL}/${path.replace(/^\//, '')}`, {
    ...init,
    headers: {
      Accept: 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...init.headers,
    },
    // O estado de acesso pode mudar a qualquer momento, então nunca faça cache das respostas da API.
    cache: 'no-store',
  })
 
  if (!res.ok) {
    let detail = res.statusText
    try {
      detail = (await res.json()).detail ?? detail
    } catch {
      /* corpo de erro não-JSON */
    }
    throw new Error(`Notoriun API ${res.status}: ${detail}`)
  }
  return res.json()
}
 
// A mídia é servida a partir da RAIZ do backend (não sob /api/v1), em caminhos
// org/curso-escopados. Derive a base do backend removendo o sufixo /api/v1.
export const BACKEND_URL = API_URL.replace(/\/api\/v1\/?$/, '')
 
/**
 * URL para a miniatura de um curso. A API armazena `thumbnail_image` como um
 * nome de arquivo puro, então o caminho completo é org/curso-escopado. URLs
 * absolutas (S3) são retornadas como estão.
 */
export function courseThumbnail(orgUuid: string, course: Course): string | null {
  const file = course.thumbnail_image
  if (!file) return null
  if (/^https?:\/\//.test(file)) return file
  return `${BACKEND_URL}/content/orgs/${orgUuid}/courses/${course.course_uuid}/thumbnails/${file}`
}
 
/**
 * URL para mídia de atividade hospedada (kind = 'video' | 'documentpdf').
 * `fileId` é o nome de arquivo armazenado no `content` da atividade.
 */
export function activityMedia(
  orgUuid: string,
  courseUuid: string,
  activityUuid: string,
  kind: 'video' | 'documentpdf',
  fileId: string
): string {
  return `${BACKEND_URL}/content/orgs/${orgUuid}/courses/${courseUuid}/activities/${activityUuid}/${kind}/${fileId}`
}

O endpoint de entrega de conteúdo vive na raiz do backend (http://localhost:1338/content/…), não sob /api/v1. E thumbnail_image é só um nome de arquivo — o caminho real é content/orgs/{org_uuid}/courses/{course_uuid}/thumbnails/{filename}. Isso espelha o serviço de mídia do frontend oficial.

Ele também define alguns tipos que você vai reusar. Adicione-os ao mesmo arquivo:

src/lib/learnhouse.ts (continuação)
export type Course = {

  activity_uuid: string

Passo 3 — O catálogo de cursos

O endpoint de listagem retorna um array JSON simples de cursos de uma organização, e funciona anonimamente para cursos públicos — nenhum token necessário. Substitua src/app/page.tsx:

src/app/page.tsx
import Link from 'next/link'
import { lhFetch, courseThumbnail, ORG_SLUG, type Course } from '@/lib/learnhouse'
 
export default async function CataloguePage() {
  // Busca a organização (pelo seu org_uuid, necessário para construir URLs de
  // miniatura) e a lista de cursos juntos. Ambas são leituras anônimas.
  const [org, courses] = await Promise.all([
    lhFetch<{ org_uuid: string }>(`orgs/slug/${ORG_SLUG}`),
    lhFetch<Course[]>(`courses/org_slug/${ORG_SLUG}/page/1/limit/50`),
  ])
 
  return (
    <main className="mx-auto max-w-5xl p-8">
      <h1 className="mb-8 text-3xl font-bold">Cursos</h1>
      <div className="grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3">
        {courses.map((course) => {
          const thumb = courseThumbnail(org.org_uuid, course)
          return (
            <Link
              key={course.course_uuid}
              href={`/courses/${course.course_uuid}`}
              className="overflow-hidden rounded-xl border transition hover:shadow-lg"
            >
              {thumb && (
                // eslint-disable-next-line @next/next/no-img-element
                <img src={thumb} alt={course.name} className="h-40 w-full object-cover" />
              )}
              <div className="p-4">
                <h2 className="font-semibold">{course.name}</h2>
                <p className="mt-1 line-clamp-2 text-sm text-gray-500">
                  {course.description}
                </p>
              </div>
            </Link>
          )
        })}
      </div>
    </main>
  )
}

Inicie o servidor de desenvolvimento:

npm run dev

Abra http://localhost:3000  e você verá seus cursos. (Se o Notoriun também estiver na :3000, execute a API na sua porta usual e o Next escolherá a :3001 — ou defina PORT.)

O segmento de caminho depois de courses/ é o course_uuid completo exatamente como retornado pela lista — ele já inclui o prefixo course_ (ex.: course_3f2a…). Passe-o literalmente; não adicione nem remova nada.

Passo 4 — A página do curso

GET /api/v1/courses/{course_uuid}/meta retorna toda a árvore de conteúdo em uma chamada: o curso mais seus chapters, cada um com suas activities. Crie src/app/courses/[uuid]/page.tsx:

src/app/courses/[uuid]/page.tsx
import Link from 'next/link'
import { lhFetch, type CourseMeta } from '@/lib/learnhouse'
 
export default async function CoursePage({
  params,
}: {
  params: Promise<{ uuid: string }>
}) {
  const { uuid } = await params
  const course = await lhFetch<CourseMeta>(`courses/${uuid}/meta`)
 
  return (
    <main className="mx-auto max-w-3xl p-8">
      <Link href="/" className="text-sm text-gray-500">← Todos os cursos</Link>
      <h1 className="mt-4 text-3xl font-bold">{course.name}</h1>
      <p className="mt-2 text-gray-600">{course.description}</p>
 
      <div className="mt-8 space-y-6">
        {course.chapters.map((chapter) => (
          <section key={chapter.chapter_uuid}>
            <h2 className="mb-2 text-lg font-semibold">{chapter.name}</h2>
            <ul className="space-y-1">
              {chapter.activities
                .filter((a) => a.published)
                .map((activity) => (
                  <li key={activity.activity_uuid}>
                    <Link
                      href={`/courses/${uuid}/${activity.activity_uuid}`}
                      className="text-blue-600 hover:underline"
                    >
                      {activity.name}
                    </Link>
                  </li>
                ))}
            </ul>
          </section>
        ))}
      </div>
    </main>
  )
}

meta aceita uma flag de query with_unpublished_activities, mas isso só retorna rascunhos para um usuário com permissão de edição. Para um site público, deixe-a de fora e filtre por activity.published como acima.

Passo 5 — O visualizador de atividade

Cada atividade carrega um activity_type e um objeto content. Renderize por tipo. Crie src/app/courses/[uuid]/[activityUuid]/page.tsx:

src/app/courses/[uuid]/[activityUuid]/page.tsx
import { lhFetch, activityMedia, ORG_SLUG, type Activity } from '@/lib/learnhouse'
 
export default async function ActivityPage({
  params,
}: {
  params: Promise<{ uuid: string; activityUuid: string }>
}) {
  const { uuid, activityUuid } = await params
  // Mídia hospedada é escopada por org/curso/atividade, então também precisamos do org_uuid.
  const [org, activity] = await Promise.all([
    lhFetch<{ org_uuid: string }>(`orgs/slug/${ORG_SLUG}`),
    lhFetch<Activity>(`activities/${activityUuid}`),
  ])
 
  return (
    <main className="mx-auto max-w-3xl p-8">
      <h1 className="mb-6 text-2xl font-bold">{activity.name}</h1>
      <ActivityBody activity={activity} orgUuid={org.org_uuid} courseUuid={uuid} activityUuid={activityUuid} />
    </main>
  )
}
 
function ActivityBody({
  activity, orgUuid, courseUuid, activityUuid,
}: {
  activity: Activity; orgUuid: string; courseUuid: string; activityUuid: string
}) {
  switch (activity.activity_type) {
    case 'TYPE_VIDEO': {
      // Vídeos do YouTube armazenam uma URL de assistir; vídeos hospedados armazenam um nome de arquivo em content.
      const c = activity.content ?? {}
      if (activity.activity_sub_type === 'SUBTYPE_VIDEO_YOUTUBE' && c.uri) {
        const id = new URL(c.uri).searchParams.get('v') ?? c.uri.split('/').pop()
        return (
          <div className="aspect-video">
            <iframe
              className="h-full w-full rounded-lg"
              src={`https://www.youtube.com/embed/${id}`}
              allowFullScreen
            />
          </div>
        )
      }
      const fileId = c.filename // inspecione o `content` da sua atividade para a chave real
      return fileId
        ? <video controls src={activityMedia(orgUuid, courseUuid, activityUuid, 'video', fileId)} className="w-full rounded-lg" />
        : <Unsupported />
    }
    case 'TYPE_DOCUMENT': {
      const fileId = activity.content?.filename
      return fileId
        ? <iframe src={activityMedia(orgUuid, courseUuid, activityUuid, 'documentpdf', fileId)} className="h-[80vh] w-full rounded-lg border" />
        : <Unsupported />
    }
    case 'TYPE_DYNAMIC':
      // Páginas dinâmicas são um documento de blocos estruturado (veja /platform/editor).
      // Renderize seus próprios componentes de bloco aqui; por ora mostra a estrutura bruta.
      return (
        <pre className="overflow-auto rounded-lg bg-gray-50 p-4 text-xs">
          {JSON.stringify(activity.content, null, 2)}
        </pre>
      )
    default:
      return <Unsupported />
  }
}
 
function Unsupported() {
  return <p className="text-gray-500">Este tipo de atividade ainda não é renderizado.</p>
}

As chaves exatas dentro de content dependem do subtipo da atividade e da sua versão de editor. Inspecione uma atividade real (GET /api/v1/activities/{activity_uuid}) na sua instância e ajuste os nomes de campo acima para corresponder. Páginas dinâmicas em particular são um documento de bloco rico — veja a documentação do Editor para o modelo de bloco.

✅ Ponto de verificação

Você agora tem um site de aprendizado público totalmente navegável — catálogo, páginas de curso, e um visualizador de atividade — com zero autenticação. Isso já é útil para qualquer curso que você marcou como público. Tudo a partir daqui é aditivo.

Parte 2 — Autenticação, matrícula e progresso

Agora adicionamos contas. A regra de ouro: tokens do Notoriun nunca alcançam o navegador. Seu app Next.js faz login no servidor, armazena os tokens no seu próprio cookie httpOnly, e os anexa ao chamar a API. Este é o padrão Backend-for-Frontend (BFF).

Navegador
Formulário de login
e-mail + senha
Route Handler do Next.js
Seu BFF
POST do formulário
POST /auth/login
Devolve access + refresh tokens
tokens no corpo
Cookie de sessão httpOnly
Tokens ficam no servidor

O navegador só guarda o cookie de sessão da sua própria aplicação — nunca os tokens do Notoriun. Para renovar, seu servidor reenvia o refresh token armazenado para GET /auth/refresh como um cabeçalho Cookie: LH_refresh=… (o endpoint só o lê a partir desse cookie).

A pegadinha do refresh. POST /api/v1/auth/login retorna access_token e refresh_token no corpo JSON. Mas GET /api/v1/auth/refresh lê o token de refresh só do cookie LH_refresh — não de um header e não do corpo. Então quando seu servidor renova, ele precisa enviar o token de refresh armazenado como o cookie LH_refresh. Nós tratamos disso em lib/session.ts abaixo.

Passo 6 — Uma sessão do lado do servidor

Crie src/lib/session.ts para ler e escrever o cookie de sessão. Ele armazena os tokens do Notoriun, questões de criptografia-em-repouso à parte, em um cookie httpOnly que o navegador não pode ler via JavaScript.

src/lib/session.ts
import { cookies } from 'next/headers'
 
const SESSION_COOKIE = 'lh_session'
 
export type Session = {
  access_token: string
  refresh_token: string
  user: { user_uuid: string; username: string; email: string }
}
 
export async function getSession(): Promise<Session | null> {
  const raw = (await cookies()).get(SESSION_COOKIE)?.value
  return raw ? (JSON.parse(raw) as Session) : null
}
 
export async function setSession(session: Session) {
  ;(await cookies()).set(SESSION_COOKIE, JSON.stringify(session), {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 60 * 60 * 24 * 30, // 30 dias, corresponde ao tempo de vida do refresh token
  })
}
 
export async function clearSession() {
  ;(await cookies()).delete(SESSION_COOKIE)
}

Passo 7 — Route Handlers de cadastro e login (o BFF)

O endpoint de login espera campos codificados em formulário username (o e-mail) e password. Crie src/app/api/auth/login/route.ts:

src/app/api/auth/login/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { API_URL } from '@/lib/learnhouse'
import { setSession } from '@/lib/session'
 
export async function POST(req: NextRequest) {
  const { email, password } = await req.json()
 
  const form = new URLSearchParams({ username: email, password })
  const res = await fetch(`${API_URL}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: form,
  })
 
  if (!res.ok) {
    const { detail } = await res.json().catch(() => ({ detail: 'Login failed' }))
    return NextResponse.json({ error: detail }, { status: res.status })
  }
 
  const { user, tokens } = await res.json()
  await setSession({
    access_token: tokens.access_token,
    refresh_token: tokens.refresh_token,
    user,
  })
  return NextResponse.json({ ok: true })
}

O cadastro cria um usuário na sua organização com POST /api/v1/users/{org_id} (corpo JSON). Crie src/app/api/auth/signup/route.ts:

src/app/api/auth/signup/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { API_URL, lhFetch, ORG_SLUG } from '@/lib/learnhouse'
 
export async function POST(req: NextRequest) {
  const body = await req.json() // { email, password, username, first_name, last_name }
 
  // Resolve o slug da organização para o seu id numérico (a rota de criação de usuário é indexada por id).
  const org = await lhFetch<{ id: number }>(`orgs/slug/${ORG_SLUG}`)
 
  const res = await fetch(`${API_URL}/users/${org.id}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  })
 
  if (!res.ok) {
    const { detail } = await res.json().catch(() => ({ detail: 'Signup failed' }))
    return NextResponse.json({ error: detail }, { status: res.status })
  }
  return NextResponse.json({ ok: true })
}

Em implantações SaaS, novas contas precisam verificar seu e-mail antes de poder fazer login. Em uma instância local self-hosted isso geralmente está desativado, então cadastro → login funciona imediatamente. Veja Autenticação para os endpoints de verificação.

Um handler de logout limpa o cookie — src/app/api/auth/logout/route.ts:

src/app/api/auth/logout/route.ts
import { NextResponse } from 'next/server'
import { API_URL } from '@/lib/learnhouse'
import { getSession, clearSession } from '@/lib/session'
 
export async function POST() {
  const session = await getSession()
  if (session) {
    // Revogação no servidor, best-effort.
    await fetch(`${API_URL}/auth/logout`, {
      method: 'DELETE',
      headers: { Authorization: `Bearer ${session.access_token}` },
    }).catch(() => {})
  }
  await clearSession()
  return NextResponse.json({ ok: true })
}

Um formulário de login

Um formulário mínimo do lado do cliente que envia ao seu BFF — src/app/login/page.tsx:

src/app/login/page.tsx
'use client'
 
import { useState } from 'react'
import { useRouter } from 'next/navigation'
 
export default function LoginPage() {
  const router = useRouter()
  const [error, setError] = useState('')
 
  async function onSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault()
    const data = Object.fromEntries(new FormData(e.currentTarget))
    const res = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    })
    if (res.ok) router.push('/')
    else setError((await res.json()).error ?? 'Login failed')
  }
 
  return (
    <main className="mx-auto max-w-sm p-8">
      <h1 className="mb-6 text-2xl font-bold">Entrar</h1>
      <form onSubmit={onSubmit} className="space-y-4">
        <input name="email" type="email" placeholder="E-mail" required className="w-full rounded border p-2" />
        <input name="password" type="password" placeholder="Senha" required className="w-full rounded border p-2" />
        <button className="w-full rounded bg-blue-600 p-2 text-white">Entrar</button>
        {error && <p className="text-sm text-red-600">{error}</p>}
      </form>
      <p className="mt-4 text-sm text-gray-500">
        Não tem conta? <a href="/signup" className="text-blue-600">Cadastre-se</a>.
      </p>
    </main>
  )
}

Um formulário de cadastro

O cadastro coleta alguns campos extras e envia para o handler de cadastro, depois faz login. Crie src/app/signup/page.tsx:

src/app/signup/page.tsx
'use client'
 
import { useState } from 'react'
import { useRouter } from 'next/navigation'
 
export default function SignupPage() {
  const router = useRouter()
  const [error, setError] = useState('')
 
  async function onSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault()
    const data = Object.fromEntries(new FormData(e.currentTarget))
 
    const signup = await fetch('/api/auth/signup', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    })
    if (!signup.ok) return setError((await signup.json()).error ?? 'Signup failed')
 
    // Faz login diretamente com as mesmas credenciais.
    const login = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email: data.email, password: data.password }),
    })
    if (login.ok) router.push('/')
    else router.push('/login') // ex.: verificação de e-mail necessária
  }
 
  return (
    <main className="mx-auto max-w-sm p-8">
      <h1 className="mb-6 text-2xl font-bold">Criar uma conta</h1>
      <form onSubmit={onSubmit} className="space-y-4">
        <input name="first_name" placeholder="Nome" required className="w-full rounded border p-2" />
        <input name="last_name" placeholder="Sobrenome" required className="w-full rounded border p-2" />
        <input name="username" placeholder="Nome de usuário" required className="w-full rounded border p-2" />
        <input name="email" type="email" placeholder="E-mail" required className="w-full rounded border p-2" />
        <input name="password" type="password" placeholder="Senha" required className="w-full rounded border p-2" />
        <button className="w-full rounded bg-blue-600 p-2 text-white">Cadastrar</button>
        {error && <p className="text-sm text-red-600">{error}</p>}
      </form>
    </main>
  )
}

Passo 8 — Requisições autenticadas e refresh

Adicione um helper que extrai o token da sessão e o renova quando expirou. Adicione ao final de src/lib/session.ts:

src/lib/session.ts (continuação)
import { API_URL } from '@/lib/learnhouse'
 
/**
 * Executa uma chamada de API como o usuário conectado. Em um 401, renova o
 * token de forma transparente e tenta novamente uma vez. Retorna null se não há sessão.
 */
export async function authedFetch<T = any>(
  path: string,
  init: RequestInit = {}
): Promise<T | null> {
  const session = await getSession()
  if (!session) return null
 
  const call = (token: string) =>
    fetch(`${API_URL}/${path.replace(/^\//, '')}`, {
      ...init,
      headers: { Accept: 'application/json', Authorization: `Bearer ${token}`, ...init.headers },
      cache: 'no-store',
    })
 
  let res = await call(session.access_token)
 
  if (res.status === 401) {
    // /auth/refresh lê o token de refresh do *cookie* LH_refresh,
    // então envie-o como um (não como um header ou corpo).
    const refreshed = await fetch(`${API_URL}/auth/refresh`, {
      headers: { Cookie: `LH_refresh=${session.refresh_token}` },
    })
    if (refreshed.ok) {
      const tokens = await refreshed.json()
      await setSession({ ...session, access_token: tokens.access_token, refresh_token: tokens.refresh_token })
      res = await call(tokens.access_token)
    }
  }
 
  if (!res.ok) throw new Error(`Notoriun API ${res.status}`)
  return res.json()
}

Passo 9 — Matrícula

As matrículas e o progresso de um aluno vivem em uma Trilha (uma por usuário por organização). Adicionar um curso à trilha é POST /api/v1/trail/add_course/{course_uuid} — mas a trilha precisa existir primeiro, ou você receberá um 404 Trail not found. A forma mais simples de garantir isso: leia a trilha uma vez (GET /api/v1/trail/org/{org_id}/trail a cria de forma lazy) imediatamente antes de matricular.

Adicione uma Server Action e conecte-a a um botão. Crie src/app/courses/[uuid]/actions.ts:

src/app/courses/[uuid]/actions.ts
'use server'
 
import { revalidatePath } from 'next/cache'
import { authedFetch } from '@/lib/session'
 
export async function enroll(courseUuid: string, orgId: number) {
  // Ler a trilha a cria se ainda não existir — necessário antes que um curso possa ser adicionado.
  // orgId vem da resposta `meta` do curso.
  await authedFetch(`trail/org/${orgId}/trail`)
  await authedFetch(`trail/add_course/${courseUuid}`, { method: 'POST' })
  revalidatePath(`/courses/${courseUuid}`)
}
 
export async function markActivityDone(courseUuid: string, activityUuid: string) {
  // add_activity cria a trilha/execução na hora, então nenhum passo prévio é necessário aqui.
  await authedFetch(`trail/add_activity/${activityUuid}`, { method: 'POST' })
  revalidatePath(`/courses/${courseUuid}`)
}

Agora um pequeno componente de cliente para o botão. Ele chama a Server Action e mostra um estado pendente. Crie src/app/courses/[uuid]/EnrollButton.tsx:

src/app/courses/[uuid]/EnrollButton.tsx
'use client'
 
import { useTransition } from 'react'
import { enroll } from './actions'
 
export default function EnrollButton({
  courseUuid,
  orgId,
  loggedIn,
}: {
  courseUuid: string
  orgId: number
  loggedIn: boolean
}) {
  const [pending, start] = useTransition()
 
  if (!loggedIn) {
    return <a href="/login" className="rounded bg-blue-600 px-4 py-2 text-white">Entre para se matricular</a>
  }
 
  return (
    <button
      disabled={pending}
      onClick={() => start(() => enroll(courseUuid, orgId))}
      className="rounded bg-blue-600 px-4 py-2 text-white disabled:opacity-50"
    >
      {pending ? 'Matriculando…' : 'Matricular-se'}
    </button>
  )
}

Passo 10 — Progresso

O progresso de um aluno vive na sua Trilha. Busque-a para a organização atual com GET /api/v1/trail/org/{org_id}/trail; ela retorna um array runs (um por curso matriculado), cada um com steps (um por atividade concluída, indexado pelo activity_id numérico) e uma contagem course_total_steps.

Agora vamos conectar tudo. Atualize a página de curso do Passo 4 para buscar a trilha de um usuário conectado, mostrar o botão Matricular-se, e renderizar um ✓ ao lado das atividades concluídas:

src/app/courses/[uuid]/page.tsx (atualizado)
import Link from 'next/link'
import { lhFetch, type CourseMeta } from '@/lib/learnhouse'
import { getSession, authedFetch } from '@/lib/session'
import EnrollButton from './EnrollButton'
 
export default async function CoursePage({
  params,
}: {
  params: Promise<{ uuid: string }>
}) {
  const { uuid } = await params
  const course = await lhFetch<CourseMeta>(`courses/${uuid}/meta`)
 
  // Extras para conectados: matrícula + atividades concluídas.
  const session = await getSession()
  let completed = new Set<number>()
  if (session) {
    const trail = await authedFetch<{ runs: any[] }>(`trail/org/${course.org_id}/trail`)
    const run = trail?.runs.find((r) => r.course?.course_uuid === course.course_uuid)
    completed = new Set(run?.steps?.map((s: any) => s.activity_id) ?? [])
  }
 
  return (
    <main className="mx-auto max-w-3xl p-8">
      <Link href="/" className="text-sm text-gray-500">← Todos os cursos</Link>
      <div className="mt-4 flex items-center justify-between gap-4">
        <h1 className="text-3xl font-bold">{course.name}</h1>
        <EnrollButton courseUuid={course.course_uuid} orgId={course.org_id} loggedIn={!!session} />
      </div>
      <p className="mt-2 text-gray-600">{course.description}</p>
 
      <div className="mt-8 space-y-6">
        {course.chapters.map((chapter) => (
          <section key={chapter.chapter_uuid}>
            <h2 className="mb-2 text-lg font-semibold">{chapter.name}</h2>
            <ul className="space-y-1">
              {chapter.activities
                .filter((a) => a.published)
                .map((activity) => (
                  <li key={activity.activity_uuid} className="flex items-center gap-2">
                    <span>{completed.has(activity.id) ? '✓' : '○'}</span>
                    <Link
                      href={`/courses/${uuid}/${activity.activity_uuid}`}
                      className="text-blue-600 hover:underline"
                    >
                      {activity.name}
                    </Link>
                  </li>
                ))}
            </ul>
          </section>
        ))}
      </div>
    </main>
  )
}

Por fim, chame markActivityDone(course_uuid, activity_uuid) do visualizador de atividade quando um aluno terminar — ex.: um botão “Marcar como concluído” (um componente de cliente usando o mesmo padrão useTransition do EnrollButton).

steps são indexados pelo id numérico da atividade, então a verificação do conjunto de concluídos usa activity.id. A resposta meta inclui tanto id quanto activity_uuid em cada atividade — id para casar o progresso, activity_uuid para roteamento.

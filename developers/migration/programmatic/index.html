Migração Programática

Este guia percorre a sequência completa de chamadas de API necessárias para construir um curso do zero — as mesmas chamadas que a interface web do Notoriun faz quando um editor navega pelo painel. Use-o como referência ao escrever seu próprio script de migração.

A URL base em todo exemplo é http://localhost:1338/api/v1 — substitua pelo domínio da sua instância.

Todos os exemplos usam um token de API (Authorization: Bearer lh_...). Um JWT de usuário funciona da mesma forma.

1. Crie o curso

curl -X POST "http://localhost:1338/api/v1/courses/?org_id=1" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'name=Introduction to Python' \
  -F 'description=A beginner-friendly Python course' \
  -F 'public=false' \
  -F 'about=Hands-on Python from zero to writing your first scripts.' \
  -F 'thumbnail_type=image' \
  -F 'thumbnail=@./thumbnail.png'

org_id é um parâmetro de query no endpoint de criação. O corpo é dados multipart form porque a mesma chamada opcionalmente envia uma imagem de miniatura ou vídeo.

CampoTipoObrigatórioNotas
namestringSimTítulo do curso
descriptionstringSimDescrição curta (uma linha)
aboutstringSimDescrição longa mostrada na página do curso
publicbooleanoSimtrue = listado publicamente, false = só membros
thumbnail_typeenumNãoimage (padrão) ou video
thumbnailarquivoNãoArquivo de imagem ou vídeo correspondente a thumbnail_type
learningsstringNãoArray codificado em JSON de objetivos de aprendizado
tagsstringNãoArray codificado em JSON de tags

A resposta é um CourseRead:

{
  "id": 42,
  "course_uuid": "course_8e3...",
  "org_id": 1,
  "name": "Introduction to Python",
  "description": "A beginner-friendly Python course",
  "about": "Hands-on Python from zero to writing your first scripts.",
  "public": false,
  "published": false,
  "thumbnail_type": "image",
  "thumbnail_image": "thumbnail.png",
  "thumbnail_video": "",
  "creation_date": "2026-04-25 10:00:00",
  "update_date": "2026-04-25 10:00:00",
  "authors": [...]
}

Capture tanto id quanto course_uuid. Você vai precisar de id (inteiro) para criar capítulos, e de course_uuid para buscar, atualizar, ou excluir o curso mais tarde.

2. Crie capítulos

Capítulos são criados um por vez com um corpo JSON:

curl -X POST "http://localhost:1338/api/v1/chapters/" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Chapter 1 — Getting set up",
    "description": "Install Python, pick an editor, write hello world.",
    "course_id": 42,
    "org_id": 1,
    "lock_type": "public"
  }'
CampoTipoObrigatórioNotas
namestringSimTítulo do capítulo
course_idinteiroSimChave primária do curso do passo 1
org_idinteiroSimMesma organização do curso
descriptionstringNãoDescrição curta
thumbnail_imagestringNãoURL ou caminho para uma miniatura
lock_typeenumNãopublic (padrão), authenticated, ou restricted

Resposta (ChapterRead):

{
  "id": 7,
  "chapter_uuid": "chapter_4d1...",
  "name": "Chapter 1 — Getting set up",
  "description": "Install Python, pick an editor, write hello world.",
  "course_id": 42,
  "org_id": 1,
  "lock_type": "public",
  "is_locked": false,
  "activities": [],
  "creation_date": "...",
  "update_date": "..."
}

Capture id — é o chapter_id que você vai passar ao criar atividades.

Capítulos aparecem na ordem em que são criados. Para reorganizá-los depois (ou para reordenar atividades dentro de um capítulo), chame PUT /api/v1/chapters/course/{course_uuid}/order com a ordenação desejada. Veja Reordenação abaixo.

3. Crie atividades

Há três famílias de endpoints de criação de atividade, dependendo do tipo de atividade:

3a. Criação genérica em JSON — POST /api/v1/activities/

Use isso para páginas dinâmicas, páginas markdown, embeds, tarefas (shell), e atividades customizadas. O corpo é ActivityCreate:

curl -X POST "http://localhost:1338/api/v1/activities/" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Hello, world",
    "chapter_id": 7,
    "activity_type": "TYPE_DYNAMIC",
    "activity_sub_type": "SUBTYPE_DYNAMIC_PAGE",
    "content": {},
    "details": {},
    "published": false,
    "lock_type": "public"
  }'
CampoTipoObrigatórioNotas
namestringSimTítulo da atividade
chapter_idinteiroSimChave primária do capítulo do passo 2
activity_typeenumNão (padrão TYPE_CUSTOM)Sempre defina isso explicitamente — o padrão raramente é o que você quer. Veja Referência de Tipos de Atividade
activity_sub_typeenumNão (padrão SUBTYPE_CUSTOM)Subtipo para o activity_type escolhido; o padrão combina com TYPE_CUSTOM e não renderiza no visualizador padrão
contentobjetoNão (padrão {})Payload JSON dependente do tipo (veja a referência). Sempre obrigatório na prática para todo tipo exceto uma tarefa recém-criada como shell.
detailsobjetoNãoMetadados dependentes do tipo (ex.: opções de player de vídeo)
publishedbooleanoNãoPadrão false
lock_typeenumNãopublic, authenticated, ou restricted

A resposta é um ActivityRead. Capture id e activity_uuid — você vai precisar de activity_uuid se planeja enviar blocos de mídia para uma página dinâmica, e para atualizar content mais tarde.

3b. Upload de vídeo hospedado — POST /api/v1/activities/video

Dados multipart form. Cria uma atividade TYPE_VIDEO / SUBTYPE_VIDEO_HOSTED em uma chamada:

curl -X POST "http://localhost:1338/api/v1/activities/video" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'name=Lesson 1 walkthrough' \
  -F 'chapter_id=7' \
  -F 'video_file=@./lesson-01.mp4;type=video/mp4' \
  -F 'details={"startTime":0,"endTime":null,"autoplay":false,"muted":false}'

chapter_id é enviado como string no formulário — ele é convertido para inteiro no servidor.

O endpoint valida Content-Type estritamente: só video/mp4 e video/webm são aceitos. A detecção automática de content-type do curl funciona para arquivos .mp4 / .webm reais, mas se o upload for rejeitado com "Video : Wrong video format", anexe ;type=video/mp4 (ou video/webm) ao argumento -F para defini-lo explicitamente.

3c. Vídeo externo — POST /api/v1/activities/external_video

Corpo JSON. Cria uma atividade TYPE_VIDEO / SUBTYPE_VIDEO_YOUTUBE que incorpora um player externo:

curl -X POST "http://localhost:1338/api/v1/activities/external_video" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Intro lecture",
    "uri": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "type": "youtube",
    "chapter_id": "7",
    "details": "{\"startTime\":0,\"endTime\":null,\"autoplay\":false,\"muted\":false}"
  }'

type aceita "youtube" ou "vimeo". chapter_id e details são ambos strings para este endpoint — details é uma string codificada em JSON que o servidor analisa.

3d. Documento PDF — POST /api/v1/activities/documentpdf

Dados multipart form. Cria uma atividade TYPE_DOCUMENT / SUBTYPE_DOCUMENT_PDF:

curl -X POST "http://localhost:1338/api/v1/activities/documentpdf" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'name=Course syllabus' \
  -F 'chapter_id=7' \
  -F 'pdf_file=@./syllabus.pdf;type=application/pdf'

Content-Type deve ser exatamente application/pdf, caso contrário o servidor retorna "Pdf : Wrong pdf format". Assim como nos uploads de vídeo, o curl detecta isso automaticamente para PDFs reais, mas ;type=application/pdf torna explícito.

3e. Tarefas (três passos)

Uma tarefa nunca é só uma atividade. É um shell de atividade + um registro Assignment + ao menos uma AssignmentTask. Pule qualquer um desses passos e os alunos verão um painel vazio. Sequência completa:

# 1. Shell da atividade
ACT=$(curl -fsS -X POST "http://localhost:1338/api/v1/activities/" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Final project",
    "chapter_id": 7,
    "activity_type": "TYPE_ASSIGNMENT",
    "activity_sub_type": "SUBTYPE_ASSIGNMENT_ANY",
    "content": {},
    "published": true
  }')
ACT_ID=$(echo "$ACT" | jq -r .id)
 
# 2. Registro Assignment (as quatro chaves estrangeiras são obrigatórias)
ASSIGN=$(curl -fsS -X POST "http://localhost:1338/api/v1/assignments/" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d "{
    \"title\":\"Final project\",
    \"description\":\"Submit your final project.\",
    \"due_date\":\"2026-12-31\",
    \"grading_type\":\"PERCENTAGE\",
    \"published\":true,
    \"org_id\":1,
    \"course_id\":42,
    \"chapter_id\":7,
    \"activity_id\":$ACT_ID
  }")
ASSIGN_UUID=$(echo "$ASSIGN" | jq -r .assignment_uuid)
 
# 3. Ao menos uma atividade — sem isso, a tarefa renderiza sem interface de envio
curl -fsS -X POST "http://localhost:1338/api/v1/assignments/$ASSIGN_UUID/tasks" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "title":"Submit your project file",
    "description":"Upload a PDF of your final project.",
    "hint":"Use a clear filename.",
    "assignment_type":"FILE_SUBMISSION",
    "contents":{},
    "max_grade_value":100
  }'

Veja Referência de Tipos de Atividade — Tarefas para a lista completa de campos, valores de grading_type suportados, e tipos de atividade assignment_type (FILE_SUBMISSION, QUIZ, FORM, CODE, SHORT_ANSWER, NUMBER_ANSWER, OTHER).

4. (Opcional) Adicione blocos de mídia a uma página dinâmica

Para atividades SUBTYPE_DYNAMIC_PAGE, imagens / vídeos / PDFs / áudio podem ser incorporados inline. O fluxo recomendado é:

  1. Envie o arquivo para um Block via POST /api/v1/blocks/{image|video|pdf|audio}.
  2. Incorpore o objeto BlockRead retornado como o atributo blockObject de um nó TipTap dentro do content da atividade.
  3. Persista o content atualizado via PUT /api/v1/activities/{activity_uuid}.

Envie um bloco de imagem (nota: o roteador de blocks rejeita tokens de API — use um JWT, ex. um gerado via a troca de token pelo admin documentada em Visão Geral → Autenticação):

curl -X POST "http://localhost:1338/api/v1/blocks/image" \
  -H "Authorization: Bearer $JWT" \
  -F 'activity_uuid=activity_91c...' \
  -F 'file_object=@./diagram.png'

Resposta:

{
  "id": 13,
  "block_uuid": "block_2a8...",
  "block_type": "BLOCK_IMAGE",
  "content": {
    "file_id": "90b8f12e-fb6b-4726-85ef-f6b511e319e5_block_2a8...",
    "file_format": "png",
    "file_name": "diagram.png",
    "file_size": 24576,
    "file_type": "image/png",
    "activity_uuid": "activity_91c..."
  },
  "org_id": 1,
  "course_id": 42,
  "chapter_id": null,
  "activity_id": 99,
  "creation_date": "...",
  "update_date": "..."
}

content.file_id é um identificador composto (um UUID, um underscore, depois o UUID do bloco). Trate-o como opaco — o renderizador o usa como está para buscar o asset em /api/v1/content/....

Você pode então referenciar esse bloco a partir de um nó TipTap blockImage dentro do content da atividade. Veja Referência de Tipos de Atividade — Página Dinâmica para o formato exato do nó.

Os quatro endpoints de bloco são simétricos:

EndpointExtensões de arquivo permitidasblock_type resultante
POST /api/v1/blocks/imagejpg, jpeg, png, gif, webpBLOCK_IMAGE
POST /api/v1/blocks/videomp4, webm, oggBLOCK_VIDEO
POST /api/v1/blocks/pdfpdfBLOCK_DOCUMENT_PDF
POST /api/v1/blocks/audiomp3, wav, ogg, m4aBLOCK_AUDIO

Todos os quatro recebem os mesmos campos de formulário: file_object (o arquivo) e activity_uuid (a atividade pai).

5. Atualize o conteúdo de uma atividade

Depois de criar uma atividade de página dinâmica (content: {}), envie quaisquer blocos de mídia, depois faça PUT do documento TipTap completo:

curl -X PUT "http://localhost:1338/api/v1/activities/activity_91c..." \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "content": {
      "type": "doc",
      "content": [
        { "type": "heading", "attrs": { "level": 1 },
          "content": [{ "type": "text", "text": "Hello, world" }] },
        { "type": "paragraph",
          "content": [{ "type": "text", "text": "Welcome to the course." }] }
      ]
    }
  }'

A lista completa de tipos de nó TipTap válidos está em Referência de Tipos de Atividade.

ActivityUpdate aceita um corpo parcial — só os campos que você definir são alterados. Campos atualizáveis:

CampoTipoNotas
namestringTítulo da atividade
contentobjetoSubstitui todo o documento de conteúdo
detailsobjetoSubstitui o objeto details
publishedbooleanoMuda para true quando estiver pronto para publicar
lock_typeenumControle de acesso
published_version / versionintVersionamento avançado — normalmente deixe como está

activity_type e activity_sub_type são tecnicamente atualizáveis no esquema, mas devem ser tratados como imutáveis na prática — o formato de content persistido não vai corresponder ao novo tipo.

Reordenação

Capítulos e as atividades dentro deles aparecem na ordem em que foram criados. Para definir explicitamente a ordenação, chame:

curl -X PUT "http://localhost:1338/api/v1/chapters/course/course_8e3.../order" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "chapter_order_by_ids": [
      { "chapter_id": 7,  "activities_order_by_ids": [{"activity_id": 99}, {"activity_id": 100}] },
      { "chapter_id": 8,  "activities_order_by_ids": [{"activity_id": 101}] }
    ]
  }'

O caminho recebe o course_uuid.

Este endpoint é destrutivo. Ele reespecifica toda a árvore do curso — todo capítulo que você omitir de chapter_order_by_ids é desvinculado do curso, e toda atividade que você omitir de activities_order_by_ids de um capítulo é desvinculada daquele capítulo. As linhas subjacentes de Activity / Chapter não são excluídas, mas são removidas do sumário do curso e os alunos não as verão mais.

Sempre:

  • Busque a árvore atual primeiro via GET /api/v1/courses/{course_uuid}/meta?with_unpublished_activities=true&slim=true,
  • Construa o payload de reordenação a partir dessa árvore (modificando só a ordem),
  • Depois faça PUT de volta.

Enviar um activities_order_by_ids vazio para um capítulo apaga as atividades daquele capítulo do curso.

Publicando

Quando a migração estiver completa, mude o curso e cada atividade para published: true:

# Publica o curso
curl -X PUT "http://localhost:1338/api/v1/courses/course_8e3..." \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{ "published": true }'
 
# Publica uma atividade
curl -X PUT "http://localhost:1338/api/v1/activities/activity_91c..." \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{ "published": true }'

Para pré-visualizar trabalho não publicado, busque a árvore do curso com a flag with_unpublished_activities:

curl "http://localhost:1338/api/v1/courses/course_8e3.../meta?with_unpublished_activities=true" \
  -H "Authorization: Bearer lh_your_api_token"

Script de ponta a ponta (bash)

O script abaixo cria um curso completo, público e publicado com um de cada tipo de atividade — uma miniatura, três capítulos, uma página dinâmica TipTap com um bloco de imagem incorporado, uma página de Markdown remoto, um embed de iframe, um MP4 hospedado, um embed do YouTube, um PDF, e uma tarefa totalmente funcional com uma atividade de File Submission. É o mesmo fluxo usado para validar esta documentação contra uma instância real.

Salve os assets que você quer usar em uma pasta (o script espera thumbnail.jpg, diagram.jpg, clip.mp4, doc.pdf) e execute-o. O tempo total de execução é menor que 10 segundos contra uma instância de dev local.

Pré-requisitos: bash, curl, jq, e python3 (para um construtor de JSON inline). O script usa a troca de token de API para JWT, então funciona tanto com um token de API lh_* (a configuração recomendada) quanto substituindo TOKEN=... por um JWT que você já tenha.

#!/usr/bin/env bash
# build-demo-course.sh — cria um curso completo de ponta a ponta via a API do Notoriun.
set -euo pipefail
 
# ── Config ───────────────────────────────────────────────────────────────────
API=http://localhost:1338/api/v1
API_TOKEN=lh_your_api_token        # token de API do plano Pro
ORG_SLUG=default                   # o slug da sua organização
ORG_ID=1                           # o id da sua organização
USER_ID=1                          # qual usuário o script vai representar
ASSETS=./assets                    # pasta contendo thumbnail.jpg, diagram.jpg, clip.mp4, doc.pdf
 
# ── 0. Gera um JWT de usuário a partir do token de API ──────────────────────
# (A maioria dos endpoints aceita o token de API diretamente, mas o caminho JWT
# é universal — incluindo os endpoints de migração assistida por IA, que rejeitam tokens de API.)
TOKEN=$(curl -fsS -X POST "$API/admin/$ORG_SLUG/auth/token" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"user_id\":$USER_ID}" | jq -r .access_token)
 
# Pequenos helpers
post_json() { curl -fsS -X POST "$1" -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d "$2"; }
put_json()  { curl -fsS -X PUT  "$1" -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d "$2"; }
 
# ── 1. Curso (multipart, com uma miniatura JPEG real) ───────────────────────
COURSE=$(curl -fsS -X POST "$API/courses/?org_id=$ORG_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -F 'name=The Complete Demo Course' \
  -F 'description=One of every activity type, built via the API' \
  -F 'about=Created end-to-end by the Notoriun migration quickstart script.' \
  -F 'public=true' \
  -F 'thumbnail_type=image' \
  -F "thumbnail=@$ASSETS/thumbnail.jpg;type=image/jpeg")
CID=$(echo "$COURSE" | jq -r .id)
CUUID=$(echo "$COURSE" | jq -r .course_uuid)
echo "→ course $CUUID (id=$CID)"
 
# ── 2. Três capítulos ────────────────────────────────────────────────────────
CH1_ID=$(post_json "$API/chapters/" \
  "{\"name\":\"1. Dynamic content\",\"description\":\"Pages, embeds, markdown\",\"course_id\":$CID,\"org_id\":$ORG_ID}" | jq -r .id)
CH2_ID=$(post_json "$API/chapters/" \
  "{\"name\":\"2. Media\",\"description\":\"Hosted video, YouTube, PDF\",\"course_id\":$CID,\"org_id\":$ORG_ID}" | jq -r .id)
CH3_ID=$(post_json "$API/chapters/" \
  "{\"name\":\"3. Interactive\",\"description\":\"Assignment\",\"course_id\":$CID,\"org_id\":$ORG_ID}" | jq -r .id)
 
# ── 3a. Página Dinâmica (conteúdo TipTap com um bloco de imagem incorporado) ─
# Cria a atividade com conteúdo vazio primeiro, depois envia um bloco de imagem,
# depois faz PUT do documento TipTap completo referenciando esse bloco.
PAGE=$(post_json "$API/activities/" \
  "{\"name\":\"Welcome page\",\"chapter_id\":$CH1_ID,\"activity_type\":\"TYPE_DYNAMIC\",\"activity_sub_type\":\"SUBTYPE_DYNAMIC_PAGE\",\"content\":{},\"published\":true}")
PAGE_UUID=$(echo "$PAGE" | jq -r .activity_uuid)
 
BLOCK=$(curl -fsS -X POST "$API/blocks/image" \
  -H "Authorization: Bearer $TOKEN" \
  -F "activity_uuid=$PAGE_UUID" \
  -F "file_object=@$ASSETS/diagram.jpg;type=image/jpeg")
echo "$BLOCK" > /tmp/lh-block.json
 
# Constrói o documento TipTap — o bloco de imagem é incorporado como um nó
# atômico `blockImage` cujo `attrs.blockObject` carrega a resposta BlockRead completa.
TIPTAP=$(python3 - <<'PY'
import json

O que você deve ver no navegador na URL impressa:

  • Página inicial do curso com a miniatura JPEG, três capítulos, um selo “7 exciting activities”, e um botão “Start Course”.
  • Página de boas-vindas com o título, parágrafo em negrito, imagem incorporada, lista com marcadores, e bloco de código com highlight de Python, além de uma barra lateral de sumário gerada a partir dos títulos.
  • Página de Markdown remoto renderizando o README do GitHub com formatação completa.
  • Exemplo de embed mostrando um artigo da Wikipédia dentro de um iframe.
  • MP4 hospedado de exemplo no player de vídeo do Notoriun.
  • Embed do YouTube com o player iframe do YouTube.
  • Documento PDF de exemplo no visualizador PDF.js incorporado com barra de ferramentas.
  • Tarefa final mostrando a descrição, data de entrega, e o widget de File Submission — mas só quando conectado. O roteador /api/v1/assignments/* rejeita requisições anônimas, então em um curso público um visualizador anônimo vê um painel vazio onde estaria o widget de tarefa. Entre na conta (ou abra via o painel) para ver a descrição, atividades, e interface de envio.

Verificando o resultado

Depois da migração, busque a árvore completa do curso e inspecione-a antes de anunciar o curso aos alunos:

curl "http://localhost:1338/api/v1/courses/$CUUID/meta?with_unpublished_activities=true&slim=true" \
  -H "Authorization: Bearer $TOKEN" | jq '
    {chapters: (.chapters | length),
     activities: (.chapters | map(.activities | length) | add)}'

slim=true omite o campo pesado content de cada atividade, o que é muito mais rápido quando você só quer verificar a estrutura.

Se algo estiver errado, todo recurso tem um endpoint DELETE — o mais seguro é excluir o curso (DELETE /api/v1/courses/{course_uuid}), que se propaga em cascata para seus capítulos, atividades, e blocos, e depois executar o script novamente.

curl -X DELETE "$API/courses/$CUUID" -H "Authorization: Bearer $TOKEN"

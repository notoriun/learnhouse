Referência de Tipos de Atividade

Toda atividade no Notoriun é descrita por dois enums e um blob JSON content:

  • activity_type — um de TYPE_DYNAMIC, TYPE_VIDEO, TYPE_DOCUMENT, TYPE_ASSIGNMENT, TYPE_CUSTOM, TYPE_SCORM.
  • activity_sub_type — uma variante mais específica dentro do tipo (ex.: SUBTYPE_VIDEO_YOUTUBE vs SUBTYPE_VIDEO_HOSTED).
  • content — um objeto JSON cujo formato depende do subtipo.

Esta página é a referência canônica do que content (e details) deve conter para cada combinação, junto com o endpoint de criação a usar.

A lista de tipos e subtipos válidos é imposta pela API como enums Python. Enviar um valor desconhecido retorna um 422 Unprocessable Entity. O enum completo é reproduzido no final desta página.

Atividades dinâmicas

activity_type: "TYPE_DYNAMIC" — páginas renderizadas dentro do visualizador de atividade.

Página Dinâmica (SUBTYPE_DYNAMIC_PAGE)

O tipo de atividade principal. content é um documento TipTap  / ProseMirror.

Endpoint de criação: POST /api/v1/activities/ (corpo JSON, veja Migração Programática).

Conteúdo inicial: comece vazio ("content": {}) e atualize depois, ou envie um documento completo na criação:

{
  "name": "Welcome to the course",
  "chapter_id": 7,
  "activity_type": "TYPE_DYNAMIC",
  "activity_sub_type": "SUBTYPE_DYNAMIC_PAGE",
  "content": {
    "type": "doc",
    "content": [
      {
        "type": "heading",
        "attrs": { "level": 1 },
        "content": [{ "type": "text", "text": "Welcome" }]
      },
      {
        "type": "paragraph",
        "content": [
          { "type": "text", "text": "This is a " },
          { "type": "text", "text": "bold", "marks": [{ "type": "bold" }] },
          { "type": "text", "text": " introduction." }
        ]
      },
      {
        "type": "bulletList",
        "content": [
          {
            "type": "listItem",
            "content": [{
              "type": "paragraph",
              "content": [{ "type": "text", "text": "Learning objective 1" }]
            }]
          },
          {
            "type": "listItem",
            "content": [{
              "type": "paragraph",
              "content": [{ "type": "text", "text": "Learning objective 2" }]
            }]
          }
        ]
      }
    ]
  }
}

A raiz deve ser { "type": "doc", "content": [...] }. Cada filho é um nó de bloco.

Tipos de bloco TipTap válidos

A API valida o conteúdo de página dinâmica contra esta lista de permissão (tipos desconhecidos são aceitos mas registrados em log):

paragraph, heading, bulletList, orderedList, listItem,
codeBlock, table, tableRow, tableHeader, tableCell,
horizontalRule, hardBreak, text,

calloutInfo, calloutWarning,
blockImage, blockVideo, blockPDF, blockAudio, blockMathEquation,
blockEmbed, blockQuiz, blockUser, blockWebPreview,
flipcard, scenarios, button, badge

Os tipos block* correspondem às extensões de nó customizadas do Notoriun. Tipos de bloco TipTap padrão (paragraph, heading, etc.) se comportam como em qualquer editor TipTap.

Marcações inline

Nós de texto ("type": "text") podem carregar marcações inline:

{ "type": "text", "text": "see link", "marks": [
  { "type": "link", "attrs": { "href": "https://example.com" } }
] }

Marcações suportadas: bold, italic, code, link, além das marcações padrão do StarterKit.

O cliente web tolera strong e em (aliases HTML) e os reescreve para bold / italic na renderização. Prefira bold / italic diretamente nos payloads da API.

Alternativa: conteúdo simplificado só de blocos

Quando a migração assistida por IA cria uma atividade de página dinâmica a partir de uma única imagem ou arquivo de áudio, ela escreve um formato legado mais simples em vez de JSON TipTap:

{
  "blocks": [
    {
      "block_uuid": "block_7522d174-...",
      "block_type": "BLOCK_IMAGE",
      "content": { "file_id": "3a80fc43-...", "file_format": "png" }
    }
  ]
}

O renderizador de página dinâmica aceita os dois formatos. Use o formato TipTap ao criar conteúdo rico; o formato blocks mais simples existe principalmente para páginas de estilo migração, só de mídia.

Incorporando blocos de mídia

Blocos de mídia (blockImage, blockVideo, blockPDF, blockAudio) são nós atômicos que apontam para um Block previamente enviado via o atributo blockObject:

{
  "type": "blockImage",
  "attrs": {
    "blockObject": {
      "block_uuid": "block_2a8...",
      "block_type": "BLOCK_IMAGE",
      "content": {
        "file_id": "block_a1b2c3...",
        "file_format": "png",
        "file_name": "diagram.png",
        "file_size": 24576,
        "file_type": "image/png",
        "activity_uuid": "activity_91c..."
      }
    },
    "size": { "width": 600 },
    "alignment": "center"
  }
}

O objeto BlockRead completo retornado por POST /api/v1/blocks/image (ou /video / /pdf / /audio) vai em attrs.blockObject. Atributos padrão por bloco:

Nó de blocoAtributos obrigatóriosAtributos opcionais
blockImageblockObjectsize: { width }, alignment (center, left, right), unsplash_*
blockVideoblockObject—
blockPDFblockObject—
blockAudioblockObject—

Blocos de código

Blocos de código incluem um atributo language consumido pelo highlight de sintaxe do lowlight:

{
  "type": "codeBlock",
  "attrs": { "language": "python" },
  "content": [
    { "type": "text", "text": "def hello():\n    print(\"Hello, world!\")" }
  ]
}

Linguagens comuns: python, javascript, typescript, java, cpp, c, rust, go, php, ruby, kotlin, csharp, swift, scala, perl, r, além de qualquer uma suportada pelo conjunto common do lowlight.

Blocos de quiz

{
  "type": "blockQuiz",
  "attrs": {
    "quizId": "quiz_1",
    "questions": [
      {
        "id": "q1",
        "question": "What does Python's print() do?",
        "options": [
          { "id": "a", "text": "Outputs to stdout", "correct": true },
          { "id": "b", "text": "Reads input", "correct": false }
        ]
      }
    ]
  }
}

O esquema exato de questions é o mesmo renderizado pelo QuizBlockComponent do editor. Inspecione um quiz real no editor e exporte o JSON se precisar de um formato autoritativo — ele evoluiu ao longo do tempo e é melhor tratado como opaco por scripts de migração.

Markdown Dinâmico (SUBTYPE_DYNAMIC_MARKDOWN)

Renderiza um arquivo Markdown buscado de uma URL remota.

{
  "name": "README",
  "chapter_id": 7,
  "activity_type": "TYPE_DYNAMIC",
  "activity_sub_type": "SUBTYPE_DYNAMIC_MARKDOWN",
  "content": { "markdown_url": "https://github.com/user/repo/raw/main/README.md" }
}

O visualizador busca e renderiza a URL a cada carregamento de página.

Embed Dinâmico (SUBTYPE_DYNAMIC_EMBED)

Renderiza uma URL arbitrária dentro de um iframe (Google Docs, Notion, Figma, etc.):

{
  "name": "Course brief",
  "chapter_id": 7,
  "activity_type": "TYPE_DYNAMIC",
  "activity_sub_type": "SUBTYPE_DYNAMIC_EMBED",
  "content": { "embed_url": "https://docs.google.com/document/d/abc123/edit" }
}

O site incorporado precisa permitir incorporação em iframe (X-Frame-Options / Content-Security-Policy). O Notoriun não consegue contornar cabeçalhos de bloqueio de frame de um destino.

Atividades de vídeo

activity_type: "TYPE_VIDEO".

Vídeo hospedado (SUBTYPE_VIDEO_HOSTED)

Criado via o endpoint multipart dedicado — você não pode criar um vídeo hospedado enviando JSON para /activities/.

O endpoint cria a atividade com published: false independentemente de qualquer campo do payload. Para publicar, siga com PUT /api/v1/activities/{activity_uuid} definindo {"published": true}. O mesmo vale para /activities/external_video e /activities/documentpdf.

Endpoint de criação: POST /api/v1/activities/video

curl -X POST "http://localhost:1338/api/v1/activities/video" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'name=Lesson 1 walkthrough' \
  -F 'chapter_id=7' \
  -F 'video_file=@./lesson-01.mp4;type=video/mp4' \
  -F 'details={"startTime":0,"endTime":null,"autoplay":false,"muted":false}'

Content-Type é verificado estritamente — só video/mp4 e video/webm são aceitos. O servidor armazena o arquivo, constrói o objeto content internamente, e retorna o ActivityRead resultante. O content persistido se parece com:

{
  "filename": "1e231d81-ae8a-4142-b165-e2b158057bc1_video.mp4",
  "activity_uuid": "activity_ec39ecc1-..."
}

filename é o nome seguro para disco que o Notoriun gerou; o player o resolve através de /api/v1/content/.... O campo de formulário details é uma string codificada em JSON com opções de player:

Chave de detailsTipoNotas
startTimenúmero (segundos)Ponto de busca ao reproduzir
endTimenúmero ou nullPonto de parada (omita para reproduzir até o final)
autoplaybooleano—
mutedbooleano—

Vídeo externo (SUBTYPE_VIDEO_YOUTUBE)

Para incorporações do YouTube e Vimeo. Note que o nome do subtipo é histórico — o mesmo subtipo também cobre o Vimeo, distinguido pelo campo type na requisição.

Endpoint de criação: POST /api/v1/activities/external_video

curl -X POST "http://localhost:1338/api/v1/activities/external_video" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Intro lecture",
    "uri": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
    "type": "youtube",
    "chapter_id": "7",
    "details": "{\"startTime\":0,\"endTime\":null,\"autoplay\":false,\"muted\":false}"
  }'
CampoTipoObrigatórioNotas
namestringSimTítulo da atividade
uristringSimURL do YouTube ou Vimeo
typeenumSim"youtube" ou "vimeo"
chapter_idstringSimID numérico do capítulo, enviado como string
detailsstringNãoOpções de player codificadas em JSON (mesmas chaves acima), padrão "{}"

O content persistido é { uri, type, activity_uuid }.

Atividades de documento

activity_type: "TYPE_DOCUMENT".

PDF (SUBTYPE_DOCUMENT_PDF)

Endpoint de criação: POST /api/v1/activities/documentpdf

curl -X POST "http://localhost:1338/api/v1/activities/documentpdf" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'name=Course syllabus' \
  -F 'chapter_id=7' \
  -F 'pdf_file=@./syllabus.pdf;type=application/pdf'

Content-Type deve ser application/pdf. O content persistido é:

{
  "filename": "9325f6f7-...-d4ecbfdc89c1_documentpdf.pdf",
  "activity_uuid": "activity_37d02abc-..."
}

O visualizador renderiza o PDF com PDF.js.

Documento genérico (SUBTYPE_DOCUMENT_DOC)

Subtipo reservado. Não há endpoint de upload dedicado — se você precisa hospedar arquivos arbitrários para download, use um upload no estilo vídeo hospedado via a interface do editor, ou envolva o arquivo em um Block e referencie-o de uma página dinâmica.

Tarefas

activity_type: "TYPE_ASSIGNMENT", activity_sub_type: "SUBTYPE_ASSIGNMENT_ANY".

Uma atividade de tarefa por si só é uma caixa vazia. O registro de atividade é só um placeholder — o título, descrição, data de entrega, tipo de correção, e quaisquer atividades de envio vivem em um registro Assignment separado. Se você criar a atividade mas pular o segundo passo, os alunos veem um painel vazio. Trate as duas chamadas como uma única transação no seu script de migração.

Uma tarefa é uma criação em três passos quando você quer que os alunos realmente enviem algo:

Passo 1 — Crie o shell da atividade

POST /api/v1/activities/ genérico:

{
  "name": "Final assignment",
  "chapter_id": 7,
  "activity_type": "TYPE_ASSIGNMENT",
  "activity_sub_type": "SUBTYPE_ASSIGNMENT_ANY",
  "content": {},
  "published": true
}

Capture id e activity_uuid da resposta.

Passo 2 — Crie o registro Assignment vinculado

POST /api/v1/assignments/ com os metadados da tarefa. Todos os IDs numéricos são obrigatórios:

{
  "title": "Final assignment",
  "description": "Submit your final project.",
  "due_date": "2026-12-31",
  "grading_type": "PERCENTAGE",
  "published": true,
  "org_id": 1,
  "course_id": 17,
  "chapter_id": 7,
  "activity_id": 145,
  "auto_grading": false,
  "anti_copy_paste": false,
  "show_correct_answers": false
}
CampoTipoObrigatórioNotas
titlestringSimMostrado no cabeçalho da tarefa
descriptionstringSimTexto do corpo
due_datestring (YYYY-MM-DD)Sim—
grading_typeenumSimALPHABET, NUMERIC, PERCENTAGE, PASS_FAIL, GPA_SCALE
org_id / course_id / chapter_id / activity_idintSimTodas as quatro chaves estrangeiras são obrigatórias
publishedbooleanoNãoPadrão false
auto_grading / anti_copy_paste / show_correct_answersbooleanoNãoTodos com padrão false

A resposta inclui assignment_uuid, que é o identificador para o passo 3.

Passo 3 — Adicione ao menos uma Atividade (Task)

Sem atividades, a tarefa renderiza a descrição mas não tem interface de envio. POST /api/v1/assignments/{assignment_uuid}/tasks:

{
  "title": "Submit your project file",
  "description": "Upload a PDF of your final project.",
  "hint": "Use a clear filename.",
  "assignment_type": "FILE_SUBMISSION",
  "contents": {},
  "max_grade_value": 100
}
CampoTipoObrigatórioNotas
titlestringSim—
descriptionstringSim—
hintstringSimPasse "" se não quiser uma dica — o campo é obrigatório no modelo
assignment_typeenumSimVeja a lista abaixo
contentsobjetoNão (padrão {})Payload dependente do tipo
max_grade_valueintNão (padrão 100)Atividades são corrigidas sobre este valor; código novo usa 100 em todo lugar
reference_filestringNãoURL ou nome de arquivo de referência

Tipos de atividade (assignment_type): FILE_SUBMISSION, QUIZ, FORM, CODE, SHORT_ANSWER, NUMBER_ANSWER, OTHER. Cada tipo de atividade interpreta contents de forma diferente — o caminho mais seguro para tipos desconhecidos é {}. Veja o grupo de endpoints /api/v1/assignments/ no Swagger UI para o esquema de contents por tipo.

Tarefas exigem autenticação para visualização, mesmo em um curso público. O roteador /api/v1/assignments/* tem um Depends(require_authenticated_user) no nível do roteador que retorna 401 para requisições anônimas, então um visualizador não autenticado de um curso público vê um painel vazio onde estaria o widget de tarefa. O esboço do curso ainda lista a atividade de tarefa, mas o título, descrição, data de entrega, atividades e interface de envio só aparecem depois do login. Não há modo de leitura pública para tarefas hoje — se os alunos precisam ler a descrição da tarefa sem entrar na conta, exponha-a em uma página dinâmica ao lado.

Custom

activity_type: "TYPE_CUSTOM", activity_sub_type: "SUBTYPE_CUSTOM".

Uma atividade de formato livre. content é qualquer objeto JSON que você quiser — a plataforma o armazena literalmente e o expõe a um renderizador customizado que você fornece no frontend. Use isso quando nenhum tipo integrado se encaixa e você tem sua própria UI para a atividade.

{
  "name": "Custom widget",
  "chapter_id": 7,
  "activity_type": "TYPE_CUSTOM",
  "activity_sub_type": "SUBTYPE_CUSTOM",
  "content": { "anything": "you want", "shape": [1, 2, 3] }
}

O Notoriun padrão não tem renderizador integrado para TYPE_CUSTOM. A atividade vai aparecer como um container vazio no visualizador do aluno até que você entregue um componente de frontend customizado para ela. Trate TYPE_CUSTOM como um gancho para seu próprio código de integração — se você ainda não tem essa integração, prefira SUBTYPE_DYNAMIC_PAGE (TipTap) ou SUBTYPE_DYNAMIC_EMBED (iframe) em vez disso.

SCORM

activity_type: "TYPE_SCORM", subtipos SUBTYPE_SCORM_12 e SUBTYPE_SCORM_2004.

Pacotes SCORM são enviados através da interface do editor — o manifesto (imsmanifest.xml) é analisado, os arquivos são extraídos para o armazenamento, e o content é preenchido com metadados de lançamento. A criação programática de atividades SCORM não está atualmente exposta como um endpoint público documentado; verifique o Swagger UI em uma instância de desenvolvimento para a interface mais recente.

class ActivityTypeEnum(str, Enum):
    TYPE_VIDEO = "TYPE_VIDEO"
    TYPE_DOCUMENT = "TYPE_DOCUMENT"
    TYPE_DYNAMIC = "TYPE_DYNAMIC"
    TYPE_ASSIGNMENT = "TYPE_ASSIGNMENT"
    TYPE_CUSTOM = "TYPE_CUSTOM"
    TYPE_SCORM = "TYPE_SCORM"

    # Dynamic
    SUBTYPE_DYNAMIC_PAGE = "SUBTYPE_DYNAMIC_PAGE"

    SUBTYPE_CUSTOM = "SUBTYPE_CUSTOM"
    # SCORM

    SUBTYPE_SCORM_2004 = "SUBTYPE_SCORM_2004"

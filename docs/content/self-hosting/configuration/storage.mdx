# Armazenamento de Conteúdo

O Notoriun suporta dois backends de armazenamento para conteúdo enviado, como imagens, vídeos e
documentos.

## Opções de Armazenamento

### Filesystem (Padrão)

Por padrão, o conteúdo enviado é armazenado no filesystem local usando um volume Docker. Esta é a
opção mais simples e funciona bem para implantações pequenas a médias.

```env
LEARNHOUSE_CONTENT_DELIVERY_TYPE=filesystem
```

O conteúdo é persistido em um volume Docker, então sobrevive a reinicializações de contêiner. O
comando `learnhouse backup` inclui o conteúdo do filesystem em seus backups.

### Armazenamento Compatível com S3

Para implantações de produção ou quando você precisa de armazenamento escalável, você pode usar
qualquer serviço de armazenamento compatível com S3:

- **AWS S3**
- **CloudFlare R2**
- **MinIO** (self-hosted)
- Qualquer outro provedor compatível com S3

```env
LEARNHOUSE_CONTENT_DELIVERY_TYPE=s3api
LEARNHOUSE_S3_API_BUCKET_NAME=learnhouse-content
LEARNHOUSE_S3_API_ENDPOINT_URL=https://s3.amazonaws.com
```

Depois de atualizar sua configuração de armazenamento, reinicie sua instância:

```bash
learnhouse stop
learnhouse start
```

<Callout type="info">
Ao usar armazenamento compatível com S3, garanta que o bucket exista e que as credenciais tenham
permissões de leitura/escrita. Para AWS S3, as credenciais normalmente são fornecidas via
variáveis de ambiente padrão da AWS ou papéis de instância.
</Callout>

## Escolhendo um Backend de Armazenamento

| Consideração | Filesystem | Compatível com S3 |
|---|---|---|
| Complexidade de configuração | Simples, funciona de imediato | Requer serviço externo ou contêiner adicional |
| Escalabilidade | Limitada pelo disco do servidor | Praticamente ilimitada |
| Backup | Incluído em `learnhouse backup` | Gerenciado separadamente pelo seu provedor de armazenamento |
| Custo | Incluído com seu servidor | Varia por provedor |
| Redundância | Disco único, sem redundância | Redundância integrada (depende do provedor) |

Para a maioria das instalações self-hosted começando agora, o armazenamento em filesystem é um
bom padrão. Você pode migrar para armazenamento compatível com S3 depois, conforme suas
necessidades crescem.

## Usando MinIO para S3 Self-Hosted

Se você quer armazenamento compatível com S3 sem depender de um provedor de nuvem, você pode
executar o MinIO junto com o Notoriun. O MinIO fornece uma API compatível com S3 na sua própria
infraestrutura.

Configure a URL do endpoint para apontar para sua instância MinIO:

```env
LEARNHOUSE_CONTENT_DELIVERY_TYPE=s3api
LEARNHOUSE_S3_API_BUCKET_NAME=learnhouse-content
LEARNHOUSE_S3_API_ENDPOINT_URL=http://minio:9000
```

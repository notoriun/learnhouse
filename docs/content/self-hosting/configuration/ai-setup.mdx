# Configuração de IA

O Notoriun inclui recursos com IA para assistência de aprendizado e edição de conteúdo. A camada
de IA é **agnóstica de provedor** — aponte para qualquer grande provedor de LLM definindo um nome
de provedor e uma chave de API. Esses recursos são opcionais e desativados por padrão.

Por baixo dos panos, o Notoriun usa [Pydantic AI](https://ai.pydantic.dev/) para geração, e
**llama-index** com **pgvector** para RAG (Geração Aumentada por Recuperação), permitindo que
assistentes de IA respondam perguntas usando o conteúdo dos seus cursos como contexto.

## Ativando a IA

Defina o provedor, uma chave de API e a flag de recurso no seu arquivo `.env`:

```env
LEARNHOUSE_IS_AI_ENABLED=true
LEARNHOUSE_AI_PROVIDER=google           # google | openai | anthropic | deepseek | moonshot | mistral | openrouter | bedrock | ollama
LEARNHOUSE_AI_API_KEY=your-api-key      # a chave única, qualquer que seja o provedor
```

Depois de atualizar seu arquivo `.env`, reinicie sua instância:

```bash
learnhouse stop
learnhouse start
```

<Callout type="info">
**Atualizando de uma configuração só-Gemini.** Nenhuma mudança de configuração é necessária: se
você só definiu `LEARNHOUSE_GEMINI_API_KEY`, `provider` cai para `google` por padrão e essa chave
é usada automaticamente (para geração **e** embeddings). A única diferença é que os modelos padrão
agora são a **família Gemini 3** (`gemini-3.5-flash`, `gemini-3.1-flash-lite`,
`gemini-3.1-pro-preview`) em vez do Gemini 2.5 — então sua chave/projeto precisa ter acesso ao
Gemini 3 (a camada Pro usa um modelo *preview*). Para permanecer nos modelos anteriores, fixe-os
explicitamente:

```env
LEARNHOUSE_AI_MODEL_FAST=gemini-2.0-flash-lite
LEARNHOUSE_AI_MODEL_STANDARD=gemini-2.5-flash
LEARNHOUSE_AI_MODEL_PRO=gemini-2.5-pro
```
</Callout>

<Callout type="warning">
O uso de IA é cobrado diretamente pelo provedor escolhido, com base nos modelos e no volume
usados.
</Callout>

## Modelos e camadas

O Notoriun mapeia recursos para três camadas de modelo. Deixe-as sem definir para usar os padrões
integrados do Gemini 3, ou sobrescreva qualquer uma delas com um nome de modelo válido para o seu
provedor.

| Variável de ambiente | Usado para | Padrão (Gemini 3) |
| --- | --- | --- |
| `LEARNHOUSE_AI_MODEL_FAST` | Títulos de chat, sugestões de follow-up, migração de curso | `gemini-3.1-flash-lite` |
| `LEARNHOUSE_AI_MODEL_STANDARD` | Chat de atividade, respostas de RAG e planejamento de curso / MagicBlocks / quadros / playgrounds nos planos gratuito e padrão | `gemini-3.5-flash` |
| `LEARNHOUSE_AI_MODEL_PRO` | Planejamento de curso / MagicBlocks / quadros / playgrounds nos planos Pro+ | `gemini-3.1-pro-preview` |

## Embeddings de RAG

A Geração Aumentada por Recuperação (perguntas e respostas de curso fundamentadas no seu
conteúdo) precisa de um **modelo de embedding**. Por padrão, os embeddings **seguem o provedor
escolhido**, usando um modelo de embedding padrão sensato:

| Provedor | Modelo de embedding padrão |
| --- | --- |
| Google | `gemini-embedding-001` |
| OpenAI (e Azure / Together / compatíveis com OpenAI) | `text-embedding-3-small` |
| Ollama (local) | `nomic-embed-text` |

Sobrescreva o provedor/modelo de embedding independentemente da geração, se quiser:

```env
LEARNHOUSE_AI_EMBEDDING_PROVIDER=openai          # padrão: igual a LEARNHOUSE_AI_PROVIDER
LEARNHOUSE_AI_EMBEDDING_MODEL=text-embedding-3-large
LEARNHOUSE_AI_EMBEDDING_DIMENSIONS=768           # padrão: 768
```

<Callout type="warning">
**Duas restrições a conhecer:**

1. **As dimensões são fixadas em 768** para corresponder à coluna pgvector. Os padrões acima
   todos produzem vetores de 768 dimensões. Se você definir `LEARNHOUSE_AI_EMBEDDING_DIMENSIONS`
   para outro valor (ou usar um modelo com um tamanho fixo diferente), você precisará migrar a
   coluna `course_embedding` e reindexar os cursos existentes.
2. **Alguns provedores não têm API de embeddings** — Anthropic, DeepSeek, Moonshot, Mistral,
   OpenRouter e Bedrock. Com um desses selecionado para geração, os embeddings caem
   automaticamente para o **Google** quando `LEARNHOUSE_GEMINI_API_KEY` está definida; caso
   contrário, defina `LEARNHOUSE_AI_EMBEDDING_PROVIDER` como `google`, `openai` ou `ollama`.
</Callout>

Recursos que não usam RAG (chat de atividade, planejamento de curso, MagicBlocks, o assistente do
editor) não precisam de embeddings e funcionam com qualquer provedor.

## Contexto de arquivo e vídeo (planejamento de curso)

O planejamento de curso pode receber **imagens, PDFs e links do YouTube** como material de
referência. O Notoriun converte cada anexo para o formato correto para o seu provedor; o que
realmente funciona depende das capacidades do próprio provedor:

| Anexo | Google Gemini | OpenAI | Anthropic (Claude) | DeepSeek / Mistral / outros |
| --- | --- | --- | --- | --- |
| Imagens | ✅ | ✅ | ✅ | ✅ em modelos com visão |
| PDFs | ✅ | ✅ (modelos com suporte a documentos) | ✅ | ⚠️ depende do modelo |
| URLs do YouTube | ✅ | ❌ | ❌ | ❌ |

Imagens e PDFs são amplamente suportados em modelos com visão/suporte a documentos. **Links do
YouTube são uma capacidade exclusiva do Gemini** — o Gemini busca o vídeo diretamente, enquanto
outros provedores não têm equivalente. Quando um tipo de anexo não é suportado, a requisição
falha com um erro claro em vez de descartá-lo silenciosamente — então, se você depende de
contexto de curso do **YouTube**, mantenha `provider: google`.

## Configuração de IA por organização

Uma vez que a IA está ativada na instância, cada organização pode ativar ou desativar a IA e
definir limites de uso a partir das suas configurações de administração. O provedor e a chave de
API são definidos uma vez no momento da implantação e compartilhados entre organizações.

## Geração de mídia (imagens e áudio)

Geração de imagem e geração de áudio / podcast (texto para fala) são caminhos **exclusivos do
Google**: eles sempre usam o SDK GenAI do Google independentemente de `LEARNHOUSE_AI_PROVIDER`,
resolvendo sua chave a partir de `LEARNHOUSE_AI_API_KEY` (quando `provider=google`) ou
`LEARNHOUSE_GEMINI_API_KEY`. Então, se você já usa Gemini, eles funcionam sem configuração extra.

Ambos os ids de modelo têm valores padrão sensatos e só precisam ser sobrescritos para adotar um
modelo mais novo/permitido:

```bash
# Geração de imagem por IA ("nano banana"). Padrão: gemini-2.5-flash-image
LEARNHOUSE_AI_IMAGE_MODEL=gemini-2.5-flash-image

# Geração de áudio / podcast por IA (Gemini TTS). Padrão: gemini-2.5-flash-preview-tts
# Todos os modelos Gemini TTS estão atualmente em preview, por isso isso é mantido configurável.
LEARNHOUSE_AI_TTS_MODEL=gemini-2.5-flash-preview-tts
```

O recurso de áudio alimenta a aba **Gerar** áudio do editor (texto para fala, um podcast de duas
vozes, ou uma fala "Speak" de voz única). O roteiro falado para os modos podcast/Speak é escrito
pelo modelo de texto padrão (`LEARNHOUSE_AI_MODEL_STANDARD`); a narração usa o modelo TTS acima.
Tudo isso é medido pelos [créditos de IA](/platform/ai).

## Limites de uso

Você pode configurar um limite de requisições por organização para controlar custos de API.
Quando um usuário excede o limite, novas requisições de IA são rejeitadas até que a janela seja
reiniciada.

## Referência de variáveis de ambiente

| Variável | Descrição |
| --- | --- |
| `LEARNHOUSE_IS_AI_ENABLED` | Interruptor geral para todos os recursos de IA (`true`/`false`). |
| `LEARNHOUSE_AI_PROVIDER` | `google`, `openai`, `anthropic`, `deepseek`, `moonshot`, `mistral`, `openrouter`, `bedrock`, ou `ollama`. Padrão `google`. |
| `LEARNHOUSE_AI_API_KEY` | Chave de API para o provedor escolhido. Não é necessária para `ollama` ou `bedrock`. |
| `LEARNHOUSE_AI_BASE_URL` | Opcional. Endpoint personalizado para provedores compatíveis com OpenAI / locais (ex.: Ollama). Definido automaticamente para OpenRouter. |
| `LEARNHOUSE_AI_MODEL_FAST` / `_STANDARD` / `_PRO` | Sobrescritas de modelo por camada (veja a tabela acima). |
| `LEARNHOUSE_AI_EMBEDDING_PROVIDER` / `_MODEL` / `_DIMENSIONS` | Sobrescritas opcionais de embedding de RAG. Padrão: mesmo provedor, modelo por provedor, 768 dimensões. |
| `LEARNHOUSE_AI_IMAGE_MODEL` | Modelo de geração de imagem do Google. Padrão `gemini-2.5-flash-image`. Caminho exclusivo do Google. |
| `LEARNHOUSE_AI_TTS_MODEL` | Modelo de texto para fala do Google para geração de áudio/podcast. Padrão `gemini-2.5-flash-preview-tts` (todos os modelos Gemini TTS estão em preview). Caminho exclusivo do Google. |
| `LEARNHOUSE_GEMINI_API_KEY` | Chave Google/Gemini. Também é o **fallback de embeddings** para provedores sem API de embeddings, e a chave usada para geração de imagem/TTS em provedores não-Google. |
| `AWS_REGION` / `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | Credenciais padrão da AWS, usadas apenas quando `provider=bedrock`. |

# Backups

Backups regulares são essenciais para proteger os dados do seu Notoriun. A CLI do Notoriun
fornece comandos integrados de backup e restauração para o banco de dados PostgreSQL.

<Callout type="warning">
O backup integrado cobre apenas o banco de dados e seu arquivo `.env`. O conteúdo enviado
(imagens, vídeos, documentos) armazenado no filesystem **não** está incluído. Veja
[Conteúdo no Filesystem](#conteúdo-no-filesystem) abaixo para recomendações.
</Callout>

## Criando um Backup

Crie um backup com um único comando:

```bash
learnhouse backup
```

Isso cria um arquivo com timestamp contendo:

- **`database.sql`** — um `pg_dump` do banco de dados PostgreSQL do Notoriun
- **`.env`** — uma cópia do arquivo de ambiente da sua instância (se presente)

Os backups são gravados em `<installDir>/backups/learnhouse-backup-<timestamp>.tar.gz`. A CLI
exibe o caminho absoluto quando o backup é concluído.

<Callout type="info">
`learnhouse backup` só funciona quando o PostgreSQL roda em um contêiner Docker local gerenciado
pela CLI. Se você usa um banco de dados externo gerenciado, use as ferramentas de backup nativas
desse provedor.
</Callout>

## Restaurando a Partir de um Backup

Para restaurar a partir de um arquivo de backup:

```bash
learnhouse restore <installDir>/backups/learnhouse-backup-<timestamp>.tar.gz
```

O comando restore reaplica o `database.sql` no contêiner de banco de dados em execução. Ele
**não** para ou reinicia os serviços — reinicie-os você mesmo se necessário.

<Callout type="warning">
Restaurar um backup sobrescreve o banco de dados. Certifique-se de que está restaurando na
instância correta.
</Callout>

## Automatizando Backups

É recomendado configurar backups automatizados usando um cron job. Por exemplo, para criar um
backup diário às 2h da manhã:

```bash
# Edite seu crontab
crontab -e

# Adicione esta linha para backups diários às 2h
0 2 * * * /usr/local/bin/learnhouse backup
```

## Retenção de Backups

Arquivos de backup se acumulam ao longo do tempo e podem consumir espaço em disco significativo.
Implemente uma política de retenção para remover backups antigos. Por exemplo, mantenha os
últimos 7 backups diários:

```bash
find <installDir>/backups -name "learnhouse-backup-*.tar.gz" -mtime +7 -delete
```

## Conteúdo no Filesystem

Quando `LEARNHOUSE_CONTENT_DELIVERY_TYPE=filesystem`, os arquivos enviados residem no host (ou em
um volume Docker) e **não** são capturados pelo `learnhouse backup`. Você é responsável por fazer
backup desse diretório separadamente — por exemplo com `rsync`, um snapshot de volume, ou um job
`tar` agendado.

Ao usar armazenamento `s3api`, confie nos recursos de versionamento, lifecycle ou replicação
entre regiões do seu provedor S3 para proteger o conteúdo enviado.

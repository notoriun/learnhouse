# Solução de Problemas

Este guia cobre problemas comuns com instâncias self-hosted do Notoriun e como resolvê-los.

## Primeiro Passo: Execute Diagnósticos

Antes de investigar problemas específicos, execute os diagnósticos integrados:

```bash
learnhouse doctor
```

Isso verifica a disponibilidade do Docker, a saúde dos contêineres, conflitos de porta,
resolução de DNS e espaço em disco. Frequentemente ele identifica a causa raiz dos problemas
automaticamente.

## Serviços Não Iniciam

**Sintomas:** `learnhouse start` falha, ou os contêineres estão parados ou reiniciando.

**Causas comuns:**

- **O Docker não está em execução.** Verifique se o Docker está em execução com `docker info`.
  Inicie o daemon do Docker se necessário.
- **Memória insuficiente.** O Notoriun requer pelo menos 2 GB de RAM. Verifique a memória
  disponível com `free -m` (Linux) ou o Monitor de Atividade (macOS).
- **Conflitos de porta.** Outro serviço pode estar usando a porta 80 ou 443. Verifique com
  `lsof -i :80` e pare o serviço conflitante. O `learnhouse doctor` também detecta conflitos de
  porta.
- **Configuração corrompida.** Execute `learnhouse setup` novamente para regenerar os arquivos de
  configuração.

## Erros de Conexão com o Banco de Dados

**Sintomas:** Os logs da aplicação mostram erros de conexão com o banco de dados, ou a aplicação
falha ao iniciar com mensagens relacionadas ao PostgreSQL.

**Passos para resolver:**

1. Execute diagnósticos para verificar a saúde dos contêineres:
   ```bash
   learnhouse doctor
   ```

2. Verifique os logs do banco de dados:
   ```bash
   learnhouse logs
   ```
   Procure por linhas de log do contêiner `db`.

3. Verifique se a string de conexão no seu arquivo `.env` corresponde à configuração do contêiner
   de banco de dados.

4. Se o contêiner de banco de dados continuar reiniciando, ele pode estar ficando sem espaço em
   disco. Verifique o espaço em disco disponível no host.

## Conflitos de Porta

**Sintomas:** Mensagens de erro sobre portas já em uso.

Verifique qual processo está usando a porta:

```bash
# Verifique a porta 80
lsof -i :80

# Verifique a porta 443
lsof -i :443
```

Pare o serviço conflitante, ou reconfigure o Notoriun para usar uma porta diferente executando
`learnhouse setup` novamente.

## Erros de Permissão de Armazenamento

**Sintomas:** O upload de arquivo falha, ou os logs mostram erros de permissão negada ao gravar
no armazenamento.

**Para armazenamento em filesystem:**

- Volumes Docker devem lidar com permissões automaticamente. Se os problemas persistirem,
  verifique se o daemon do Docker tem as permissões apropriadas no filesystem do host.

**Para armazenamento S3:**

- Verifique se suas credenciais S3 têm permissões de leitura e escrita no bucket configurado.
- Verifique se o nome do bucket (`LEARNHOUSE_S3_API_BUCKET_NAME`) e a URL do endpoint
  (`LEARNHOUSE_S3_API_ENDPOINT_URL`) estão corretos no seu arquivo `.env`.
- Teste a conectividade com o endpoint S3 a partir do servidor.

## Problemas de Autenticação

**Sintomas:** Usuários não conseguem fazer login, ou as sessões expiram imediatamente.

- Verifique se `NEXTAUTH_SECRET` está definido e não mudou desde o último reinício. Alterar o
  segredo invalida todas as sessões existentes.
- Verifique se `LEARNHOUSE_COOKIE_DOMAIN` corresponde ao seu domínio real. Um domínio de cookie
  incorreto impede que a autenticação funcione.
- Se estiver usando SSL, garanta que `NEXTAUTH_URL` use `https://`.

## Problemas de Desempenho

**Sintomas:** Carregamento lento de páginas, timeouts, ou alto uso de recursos.

1. Execute diagnósticos:
   ```bash
   learnhouse doctor
   ```

2. Revise os logs da aplicação em busca de erros ou operações lentas:
   ```bash
   learnhouse logs
   ```

3. Verifique os limites de recursos dos seus contêineres:
   ```bash
   learnhouse deployments
   ```

4. Considere aumentar os recursos do servidor (RAM, CPU) se o uso estiver consistentemente alto.

5. Se estiver usando armazenamento em filesystem com uma grande quantidade de conteúdo, considere
   migrar para armazenamento compatível com S3.

## Reiniciando sua Instância do Zero

<Callout type="warning">
Reiniciar sua instância do zero exclui todos os dados. Crie um backup primeiro se quiser
preservar algum dado.
</Callout>

Se você precisa começar do zero:

```bash
# Faça backup dos dados atuais (opcional)
learnhouse backup

# Pare todos os serviços
learnhouse stop

# Execute a instalação novamente
learnhouse setup

# Inicie do zero
learnhouse start
```

## Obtendo Ajuda

Se você não conseguir resolver um problema usando este guia:

1. Execute `learnhouse doctor` e inclua a saída no seu relatório.
2. Verifique as [issues do GitHub do Notoriun](https://github.com/notoriun/learnhouse/issues)
   para problemas conhecidos e soluções.
3. Abra uma nova issue com detalhes sobre seu problema, incluindo a saída de log relevante e seu
   ambiente (SO, versão do Docker, RAM).

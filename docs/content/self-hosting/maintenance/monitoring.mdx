# Monitoramento

Monitorar sua instância self-hosted do Notoriun ajuda você a identificar problemas cedo e a
garantir uma experiência confiável para seus usuários.

## Verificações de Saúde do Serviço

A CLI oferece três comandos complementares:

```bash
learnhouse status    # status rápido de contêiner para cada serviço
learnhouse health     # PostgreSQL, Redis, endpoint HTTP de saúde, disco, recursos
learnhouse doctor     # diagnósticos profundos (Docker, portas, DNS, validação de ambiente, logs)
```

Você também pode verificar o endpoint de saúde da aplicação diretamente:

```bash
curl http://localhost/api/v1/health
```

## Visualizando Logs

Acompanhe os logs de todos os contêineres:

```bash
learnhouse logs
```

## O Que Monitorar

### Saúde da Aplicação

- Execute `learnhouse doctor` regularmente para verificar se todos os serviços estão em execução
  e saudáveis
- Fique atento a reinícios de contêiner, que podem indicar problemas de memória ou erros de
  aplicação

### Uso de Disco

- Monitore o espaço em disco, especialmente se estiver usando armazenamento em filesystem para
  conteúdo enviado
- O tamanho do banco de dados cresce ao longo do tempo conforme mais conteúdo é criado
- Imagens e logs do Docker também consomem espaço em disco

### Uso de Memória

- O Notoriun requer pelo menos 2 GB de RAM
- Monitore o consumo de memória para garantir que o servidor não está fazendo swap, o que degrada
  o desempenho

### Desempenho do Banco de Dados

- Fique atento a consultas lentas nos logs da aplicação
- Monitore a contagem de conexões do PostgreSQL

## Recomendações de Monitoramento

Para implantações de produção, considere configurar:

- **Monitoramento de uptime** -- use um serviço externo para verificar se sua instância do
  Notoriun está acessível (ex.: monitore `http://seu-dominio/api/v1/health`)
- **Alertas de espaço em disco** -- seja notificado antes que o espaço em disco se esgote
- **Agregação de logs** -- envie logs para um sistema de logging centralizado para facilitar a
  análise
- **Monitoramento de contêiner** -- ferramentas como as estatísticas integradas do Docker,
  cAdvisor, ou Prometheus com node-exporter podem rastrear o uso de recursos ao longo do tempo

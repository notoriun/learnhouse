# Atualizações

Manter o Notoriun atualizado garante que você tenha os recursos, correções de bugs e patches de
segurança mais recentes.

## Atualizando o Notoriun

Use o comando integrado `update`. Ele faz backup do seu banco de dados, baixa a nova imagem,
migra o conteúdo enviado para um volume persistente, reinicia a stack e aplica migrações de banco
de dados.

```bash
# Atualizar para a versão mais recente
npx learnhouse update

# Atualizar para uma versão específica
npx learnhouse update --to 1.4.2
# ou usando a forma curta:
npx learnhouse update -v 1.4.2
```

| Flag | Descrição |
|---|---|
| `-v, --to <version>` | Baixa uma tag de imagem específica (ex.: `1.4.2`, `v1.4.2`). Padrão: `latest`. |
| `--migrate` | Executa migrações de banco de dados sem perguntar |
| `--no-migrate` | Pula migrações de banco de dados sem perguntar |
| `--no-backup` | Pula o backup de banco de dados pré-atualização (não recomendado para produção) |

<Callout type="info">
O comando update cria um backup do banco de dados automaticamente antes de fazer qualquer
mudança. O backup é salvo em `{installDir}/backups/db-pre-upgrade-{timestamp}.sql.gz`.
</Callout>

## O Que o `update` Faz

O comando executa estes passos em ordem:

1. **Backup do banco de dados** — `pg_dump` para `./backups/` (pulado com `--no-backup`)
2. **Baseline do Alembic** — marca o schema atual para instalações anteriores ao rastreamento do
   Alembic (uma vez, idempotente)
3. **Atualização da tag de imagem** — reescreve a tag no `docker-compose.yml`
4. **Migração do volume de conteúdo** — move a mídia enviada para um volume Docker nomeado, para
   que sobreviva a futuras recriações de contêiner (uma vez, idempotente)
5. **Download da imagem** — `docker compose pull` busca a nova imagem
6. **Reinício da stack** — `docker compose down && docker compose up -d --pull always`
7. **Espera de saúde** — consulta `/api/v1/health` até a aplicação responder
8. **Migrações de banco de dados** — `alembic upgrade head` (perguntado a menos que
   `--migrate`/`--no-migrate` seja passado)

## Procedimento de Atualização Recomendado

```bash
# 1. Revise as notas de versão
# https://github.com/notoriun/learnhouse/releases

# 2. Execute a atualização (o backup é criado automaticamente)
npx learnhouse update

# 3. Verifique se todos os serviços estão saudáveis
npx learnhouse doctor

# 4. Verifique os logs em busca de erros
npx learnhouse logs
```

## Migrações de Banco de Dados

O Notoriun usa o [Alembic](https://alembic.sqlalchemy.org/) para evoluir o schema do banco de
dados entre versões. Depois que o novo contêiner inicia, a CLI pergunta:

```
? Executar migrações de banco de dados agora? › Yes / No
```

- **Yes** — executa `alembic upgrade head` no contêiner da aplicação. Recomendado.
- **No** — pula as migrações. Você pode executá-las manualmente depois.

Para pular a pergunta, passe `--migrate` (sempre executar) ou `--no-migrate` (sempre pular).

<Callout type="warning">
Se você pular as migrações, a nova versão da aplicação pode apresentar erros até que elas sejam
aplicadas. Execute-as manualmente quando estiver pronto:

```bash
docker compose exec learnhouse-app sh -c "cd /app/api && uv run alembic upgrade head"
```
</Callout>

### Instalações Criadas Antes da v1.3

Instalações antigas do Notoriun criaram seu schema via `create_all` do SQLAlchemy, sem
rastreamento do Alembic. O comando update detecta isso automaticamente e marca o schema atual
como a baseline antes de executar qualquer migração incremental — então `upgrade head` aplica
apenas as mudanças novas em vez de repetir tudo.

## Revertendo uma Atualização

Se uma atualização causar problemas, restaure a partir do backup pré-atualização:

```bash
# Liste os backups disponíveis
ls {installDir}/backups/

# Restaure o banco de dados
npx learnhouse restore backups/db-pre-upgrade-<timestamp>.sql.gz

# Revert a tag de imagem no docker-compose.yml para a versão anterior
# (edite o arquivo: mude image: ghcr.io/notoriun/learnhouse/app:<nova> de volta para <antiga>)

# Reinicie na imagem antiga
npx learnhouse start
```

Backups são nomeados `db-pre-upgrade-{timestamp}.sql.gz` quando criados pelo `update`, e
`learnhouse-backup-{timestamp}.tar.gz` quando criados pelo comando `backup`. O backup
pré-atualização criado pelo `update` inclui apenas o dump do banco de dados; para também
preservar seu `.env`, execute `npx learnhouse backup` manualmente antes de atualizar.

<Callout type="warning">
Arquivos enviados armazenados no filesystem (no volume Docker `learnhouse_content_*`) **não**
estão incluídos no backup do banco de dados. Para fazer backup dos arquivos enviados, use
`docker volume export` ou um snapshot em nível de volume fornecido pela sua plataforma de
hospedagem.
</Callout>

## Verificando Atualizações

A CLI verifica automaticamente se há uma nova versão a cada vez que você executa um comando e
exibe um aviso se houver uma disponível.

Revise as [notas de versão do Notoriun](https://github.com/notoriun/learnhouse/releases) antes de
atualizar, para entender o que mudou. Algumas atualizações podem incluir:

- Novos recursos ou mudanças de interface
- Migrações de banco de dados (aplicadas automaticamente quando você aceita a pergunta ou passa
  `--migrate`)
- Mudanças de configuração que podem exigir a atualização do seu arquivo `.env`
- Mudanças que quebram compatibilidade (raras, documentadas nas notas de versão com um guia de
  migração)

# Logs de Auditoria

Logs de auditoria fornecem um registro detalhado de todas as ações realizadas na plataforma,
dando aos administradores visibilidade completa sobre quem fez o quê e quando. Isso é essencial
para conformidade, monitoramento de segurança, e solução de problemas.

<Callout>
Logs de auditoria exigem um plano Enterprise.
</Callout>

## O Que É Capturado

Toda mutação (criação, atualização, exclusão) na plataforma é registrada com os seguintes
detalhes:

| Campo | Descrição |
|---|---|
| Usuário | Quem realizou a ação (nome de usuário e ID). |
| Ação | O método HTTP (POST, PUT, DELETE, PATCH). |
| Recurso | O que foi afetado (ex.: `/courses`, `/users`). |
| ID do recurso | O item específico que foi modificado. |
| Código de status | O status de resposta HTTP. |
| Endereço IP | A origem da requisição. |
| Timestamp | Quando a ação ocorreu. |
| Payload | O corpo da requisição (com dados sensíveis removidos). |

## Tratamento de Dados Sensíveis

Logs de auditoria removem automaticamente campos sensíveis dos payloads de requisição antes de
armazená-los. Campos como `password`, `token`, `secret`, e chaves similares são redigidos para
evitar que dados sensíveis apareçam nos logs.

## Filtragem e Busca

Você pode filtrar logs de auditoria por:

- Usuário (ID, nome de usuário, ou nome completo)
- Tipo de ação
- Tipo e ID de recurso
- Código de status HTTP
- Endereço IP
- Intervalo de datas

## Exportação CSV

Logs de auditoria podem ser exportados como arquivos CSV para análise offline, relatórios de
conformidade, ou integração com ferramentas SIEM externas.

## Desempenho

As entradas de log de auditoria são armazenadas em buffer no Redis e enviadas ao banco de dados
em lotes a cada 60 segundos. Isso garante que o log não impacte o desempenho da plataforma,
mesmo sob uso intenso.

# WorkOS

O WorkOS fornece SSO empresarial através de uma API unificada que suporta tanto provedores de
identidade SAML quanto OIDC. Ele inclui um portal admin que permite que administradores de
organização configurem seu provedor de identidade sem envolvimento de desenvolvedores.

<Callout>
Exige que as variáveis de ambiente `WORKOS_API_KEY` e `WORKOS_CLIENT_ID` estejam definidas.
</Callout>

## Recursos

- **Portal Admin** — O WorkOS fornece um portal hospedado onde administradores de organização
  podem configurar e gerenciar sua conexão com o IdP diretamente.
- **SAML e OIDC** — Suporta ambos os protocolos através de uma única integração.
- **Provisionamento Automático de Usuário** — Cria automaticamente contas no Notoriun a partir
  de perfis do IdP.
- **Restrições de Domínio** — Restringe o acesso a domínios de e-mail específicos.
- **Atribuição de Papel Padrão** — Atribui um papel padrão a usuários recém-provisionados.

## Configuração

| Campo | Obrigatório | Descrição |
|---|---|---|
| `organization_id` | Sim (ou `connection_id`) | ID de Organização do WorkOS, criado automaticamente ou via o Portal Admin. |
| `connection_id` | Sim (ou `organization_id`) | ID de Conexão do WorkOS, tipicamente gerenciado via o Portal Admin. |

Você precisa de um `organization_id` (para SSO em nível de organização) ou um `connection_id`
(para uma conexão específica). Na maioria dos casos, você vai usar o `organization_id` e deixar
os administradores configurarem a conexão através do Portal Admin.

## Variáveis de Ambiente

| Variável | Descrição |
|---|---|
| `WORKOS_API_KEY` | Sua chave de API do WorkOS. |
| `WORKOS_CLIENT_ID` | Seu Client ID do WorkOS. |

## Passos de Configuração

1. Crie uma [conta WorkOS](https://workos.com) e obtenha sua chave de API e Client ID.
2. Defina as variáveis de ambiente `WORKOS_API_KEY` e `WORKOS_CLIENT_ID` na sua implantação do
   Notoriun.
3. Nas configurações da organização, selecione **WorkOS** como o provedor de SSO.
4. Use o link do Portal Admin para configurar a conexão com o provedor de identidade (SAML ou
   OIDC).
5. Usuários com domínios de e-mail correspondentes já podem entrar via SSO.

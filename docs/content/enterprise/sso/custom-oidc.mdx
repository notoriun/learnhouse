# OIDC Customizado

O provedor OIDC Customizado permite conectar o Notoriun diretamente a qualquer provedor de
identidade compatível com OpenID Connect 1.0. Isso é ideal para organizações que querem usar seu
IdP existente sem passar por um intermediário de terceiros.

## Provedores Compatíveis

Qualquer provedor compatível com OIDC funciona, incluindo:

- **Azure AD / Microsoft Entra ID**
- **Okta**
- **Google Workspace**
- **Keycloak**
- **Auth0**
- **OneLogin**
- **Ping Identity**

## Configuração

| Campo | Obrigatório | Descrição |
|---|---|---|
| `issuer_url` | Sim | A URL do Issuer OIDC. O Notoriun a usa para autodescobrir os endpoints via `/.well-known/openid-configuration`. |
| `client_id` | Sim | Client ID OAuth 2.0 do seu provedor de identidade. |
| `client_secret` | Sim | Client Secret OAuth 2.0 do seu provedor de identidade. |
| `scopes` | Não | Scopes OAuth separados por espaço. Padrão: `openid email profile`. |

## Exemplos de URL do Issuer

| Provedor | Formato da URL do Issuer |
|---|---|
| Azure AD | `https://login.microsoftonline.com/{tenant-id}/v2.0` |
| Okta | `https://{your-domain}.okta.com` |
| Google Workspace | `https://accounts.google.com` |
| Keycloak | `https://{host}/realms/{realm}` |
| Auth0 | `https://{your-domain}.auth0.com` |

## Passos de Configuração

1. Registre o Notoriun como uma aplicação no seu provedor de identidade e obtenha um Client ID e
   Client Secret.
2. Defina a URI de callback/redirect no seu IdP para a URL de callback SSO do Notoriun.
3. Nas configurações da organização, selecione **OIDC Customizado** como o provedor de SSO.
4. Insira a URL do Issuer, Client ID, e Client Secret.
5. Usuários com domínios de e-mail correspondentes já podem entrar via SSO.

<Callout type="info">
O Notoriun usa OIDC Discovery para encontrar automaticamente os endpoints de autorização, token,
e userinfo a partir da URL do issuer. Certifique-se de que seu IdP exponha um documento
`/.well-known/openid-configuration`.
</Callout>

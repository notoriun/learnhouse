# Comandos

Referência completa de todos os comandos da CLI do Notoriun.

## `setup`

Assistente interativo que gera uma implantação Docker Compose completa. Veja
[Assistente de Instalação](/cli/setup-wizard) para detalhes.

```bash
npx learnhouse@latest setup
```

| Flag | Descrição |
|---|---|
| `--ci` | Modo não interativo com padrões (para CI/automação) |
| `--name <name>` | Nome da instalação (padrão: `default`) |
| `--domain <domain>` | Nome de domínio (padrão: `localhost`) |
| `--port <port>` | Porta HTTP (padrão: `80`) |
| `--admin-email <email>` | E-mail do admin (padrão: `admin@school.dev`) |
| `--admin-password <password>` | Senha do admin (obrigatória no modo `--ci`) |
| `--org-name <name>` | Nome de exibição da organização (padrão: `Default Organization`) |
| `--org-slug <slug>` | Slug da organização usado em URLs (padrão: `default`) |
| `--channel <channel>` | Canal de release: `stable` ou `dev` (padrão: `stable`) |
| `--no-start` | Pula o início dos serviços após a instalação |
| `--external-db <uri>` | Usa um Postgres externo em vez do banco em contêiner |
| `--external-redis <uri>` | Usa um Redis externo em vez do Redis em contêiner |
| `--docker-ipv6` | Ativa IPv6 na rede do compose (necessário para bancos externos só-IPv6) |

<Callout type="info">
Use `--org-slug` para definir um prefixo de URL customizado (ex.: `--org-slug acme` → usuários
navegam em `/orgs/acme`). O padrão é `default`.
</Callout>

## `start`

Inicia todos os contêineres Docker da sua implantação.

```bash
npx learnhouse start
```

## `stop`

Para todos os contêineres em execução sem remover volumes de dados.

```bash
npx learnhouse stop
```

## `status`

Mostra o status em tempo real de cada contêiner do Notoriun.

```bash
npx learnhouse status
```

Exibe o nome de cada serviço, estado do contêiner, resultado da verificação de saúde, e contagem
de reinícios.

## `health`

Executa verificações de saúde contra a implantação em execução e reporta os resultados.

```bash
npx learnhouse health
```

Verifica:
- Estado de execução e saúde do contêiner
- Conectividade com PostgreSQL (TCP + consulta)
- Ping do Redis
- Endpoint HTTP de saúde (`/api/v1/health`)
- Uso de disco
- Consumo de memória e CPU

## `logs`

Acompanha os logs de todos os contêineres em tempo real.

```bash
npx learnhouse logs
```

## `config`

Exibe os metadados atuais da instalação — versão, diretório, URL, slug da organização, e
localizações de arquivo.

```bash
npx learnhouse config
```

## `update`

Atualiza o Notoriun para a versão mais recente ou uma versão específica. Veja
[Atualizações](/self-hosting/maintenance/updates) para detalhes.

```bash
# Atualiza para a versão mais recente
npx learnhouse update

# Atualiza para uma versão específica
npx learnhouse update --to 1.4.2
# ou usando a forma curta:
npx learnhouse update -v 1.4.2
```

| Flag | Descrição |
|---|---|
| `-v, --to <version>` | Baixa uma tag de imagem específica de `ghcr.io/notoriun/learnhouse/app` (ex.: `1.4.2`, `v1.4.2`). Padrão: `latest`. |
| `--migrate` | Executa migrações de banco de dados automaticamente após reiniciar (sem pergunta) |
| `--no-migrate` | Pula migrações de banco de dados sem perguntar |
| `--no-backup` | Pula o backup de banco de dados pré-atualização (não recomendado para produção) |

**O que o `update` faz, em ordem:**

1. Cria um backup do banco de dados (a menos que `--no-backup`)
2. Marca uma baseline do Alembic se seu banco nunca foi migrado (instalações criadas antes da v1.3)
3. Reescreve a tag de imagem no `docker-compose.yml`
4. Migra a mídia enviada para um volume Docker persistente (uma vez, idempotente)
5. Baixa a nova imagem (`docker compose pull`)
6. Reinicia a stack com `--pull always`
7. Espera o endpoint de saúde responder
8. Executa `alembic upgrade head` (a menos que `--no-migrate`)

<Callout type="warning">
Se o passo de migração falhar, a CLI exibe o comando de rollback e sai com um código
diferente de zero. Seu backup pré-atualização está em `{installDir}/backups/`. Para reverter:
restaure o backup, revert a tag de imagem no `docker-compose.yml`, e execute
`npx learnhouse start`.
</Callout>

## `backup`

Cria um backup de banco de dados como um arquivo `.tar.gz` contendo um `pg_dump` e, opcionalmente,
seu arquivo `.env`.

```bash
npx learnhouse backup
```

Backups são salvos em `{installDir}/backups/learnhouse-backup-{timestamp}.tar.gz`.

O prompt de backup permite escolher entre criar um novo backup ou restaurar de um existente.
Passe `--restore` para pular o prompt.

## `restore`

Restaura um banco de dados a partir de um arquivo de backup. Isso sobrescreve o banco de dados
atual.

```bash
npx learnhouse restore <archive.tar.gz>
```

Alternativamente:

```bash
npx learnhouse backup --restore <archive.tar.gz>
```

<Callout type="warning">
Restore só funciona com bancos de dados locais (Docker), não com conexões Postgres externas.
Reinicie os serviços depois de restaurar: `npx learnhouse stop && npx learnhouse start`.
</Callout>

O dump usa `--clean --if-exists`, então pode ser reaplicado em um banco de dados existente sem
erros (as tabelas são excluídas e recriadas). Se o arquivo `.env` foi incluído no backup, você
será perguntado se quer restaurá-lo.

## `doctor`

Executa diagnósticos abrangentes para identificar problemas.

```bash
npx learnhouse doctor
```

Verifica:
- Instalação do Docker e status do daemon
- Disponibilidade do Docker Compose v2
- Saúde do contêiner e contagens de reinício
- Disponibilidade de porta
- Resolução de DNS (para domínios não-localhost)
- Espaço em disco (avisa abaixo de 1 GB)
- Tamanhos de volume Docker
- Análise de log (busca por erros recentes)
- Validação do `.env` (variáveis obrigatórias, tamanho de segredo)
- Atualidade da imagem (compara o digest local com o registry)

## `deployments`

Visualiza e gerencia implantações na máquina atual.

```bash
npx learnhouse deployments
```

Recursos:
- Lista todas as implantações do Notoriun com status de contêiner
- Escala limites de memória para `learnhouse-app`, `db`, e `redis`
- Visualiza o uso atual de recursos via `docker stats`

## `env`

Editor interativo de variáveis de ambiente. Edite variáveis por categoria:

- Domínio e Hospedagem
- Banco de Dados e Redis
- Segurança
- IA
- E-mail (só Resend — edite o `.env` diretamente para definir credenciais SMTP)
- Armazenamento S3
- OAuth

```bash
npx learnhouse env
```

Valores secretos são mascarados na exibição. Opcionalmente reinicia os serviços após as
mudanças.

## `shell`

Abre um shell interativo (`/bin/sh`) dentro de um contêiner em execução.

```bash
npx learnhouse shell
```

Exibe uma lista de contêineres em execução para escolher.

## `dev`

Inicia um ambiente de desenvolvimento local. Veja [Modo de Desenvolvimento](/cli/dev-mode) para
detalhes.

```bash
npx learnhouse dev
```

| Flag | Descrição |
|---|---|
| `--ee` | Ativa recursos da Edição Enterprise (mantém a pasta `ee/` ativa) |
| `--admin-email <email>` | E-mail do admin (padrão: `admin@school.dev`) |
| `--admin-password <password>` | Senha do admin (pula o prompt interativo) |

## Solução de Problemas

### Contêineres reiniciam em loop

Execute `npx learnhouse doctor` — ele analisa os logs e revela a causa raiz. Causas comuns:
- Variável de ambiente obrigatória ausente no `.env`
- Conflito de porta (outro processo está usando a porta 80 ou 5432)
- Corrupção do volume do Postgres (restaure a partir do backup)

### A migração do `update` falha

Se `npx learnhouse update` reportar uma falha de migração:

```bash
# 1. Restaure seu backup pré-atualização
npx learnhouse restore backups/db-pre-upgrade-*.sql.gz

# 2. Revert a tag de imagem no docker-compose.yml para a versão anterior
# (abra o arquivo e mude image: ghcr.io/notoriun/learnhouse/app:<nova> de volta para <antiga>)

# 3. Reinicie na imagem antiga
npx learnhouse start
```

Depois verifique a [página de releases do Notoriun](https://github.com/notoriun/learnhouse/releases)
e as [issues do GitHub](https://github.com/notoriun/learnhouse/issues) para sua versão antes de
tentar novamente.

### Banco de dados inacessível após atualização

O contêiner `learnhouse-db` pode precisar de um momento após a inicialização. Espere 20-30
segundos e execute `npx learnhouse health`. Se as verificações de saúde continuarem falhando,
execute `npx learnhouse logs` para ver os logs do Postgres.

### Erros de `restore`: "relation already exists"

O comando restore usa `pg_dump --clean --if-exists`, que exclui tabelas existentes antes de
recriá-las. Se você ver esse erro, seu backup foi criado com uma versão mais antiga da CLI
(antes da v1.4.8). Como solução alternativa:

```bash
# Exclui e recria o banco de dados, depois restaura
docker compose exec db psql -U learnhouse -c "DROP DATABASE learnhouse; CREATE DATABASE learnhouse;"
npx learnhouse restore <backup.tar.gz>
```

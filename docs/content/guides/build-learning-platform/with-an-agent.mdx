# Deixe um Agente Construir

Se você preferir não digitar cada arquivo, entregue o trabalho a um agente de código. Esta
página explica como direcionar um agente (Claude Code, Cursor, Windsurf, Copilot, etc.) para
construir a mesma plataforma de aprendizado headless descrita em
[Faça Você Mesmo](/guides/build-learning-platform/do-it-yourself), usando a
**[Especificação para o Agente](/guides/build-learning-platform/agent-spec)** autocontida.

A especificação é escrita *para o modelo*: ela declara o objetivo, o contrato exato de API
extraído do código do Notoriun, o layout de arquivos, as regras de autenticação, e critérios
claros de aceitação. Você fornece três fatos sobre sua instância e deixa o agente fazer o resto.

<Callout type="info">
Isso ainda produz **seu** código na **sua** máquina — o agente só está fazendo a digitação.
Revise o resultado da mesma forma que revisaria o PR de um colega.
</Callout>

## O que você vai precisar

- Um agente de código com acesso de escrita de arquivo e terminal (ex.: **Claude Code**).
- Uma instância do Notoriun em execução e sua URL base de API (ex.: `http://localhost:1338/api/v1`).
- O **slug da sua organização** e ao menos um **curso público e publicado**.
- Credenciais de teste (um e-mail + senha com os quais você pode se cadastrar) se quiser que o
  agente verifique o fluxo autenticado.

## Como fazer

<Steps>

### Abra a Especificação para o Agente

Vá para a página **[Especificação para o Agente](/guides/build-learning-platform/agent-spec)** e
copie todo o bloco de especificação.

### Preencha as três lacunas

No topo da especificação há uma pequena seção de **Configuração**. Substitua os placeholders
pelos seus valores:

- `API_BASE` — a URL base da sua API (ex.: `http://localhost:1338/api/v1`)
- `ORG_SLUG` — o slug da sua organização
- `TEST_EMAIL` / `TEST_PASSWORD` — opcional, para verificar login/matrícula

### Cole no seu agente

Inicie uma nova sessão de agente em um diretório vazio e cole a especificação preenchida como
sua primeira mensagem. Um bom prompt inicial:

> Construa o projeto descrito na especificação abaixo. Trabalhe neste diretório, crie todos os
> arquivos, instale as dependências, e execute o servidor de desenvolvimento quando terminar.
> Me pergunte antes de fazer qualquer coisa destrutiva.
>
> _(cole a especificação aqui)_

### Revise e execute

Quando o agente terminar, ele deve ter estruturado o app, escrito os arquivos, e iniciado
`npm run dev`. Abra a URL que ele reportar e percorra: catálogo → curso → atividade → cadastro →
login → matrícula → progresso.

### Itere

Se algo estiver errado (uma URL de mídia que não carrega, um tipo de atividade que não é
renderizado), diga ao agente o que você viu. A especificação inclui as notas de solução de
problemas necessárias para corrigir os casos comuns.

</Steps>

## Como é o "pronto"

Os critérios de aceitação da especificação pedem que o agente confirme:

1. O catálogo lista seus cursos públicos.
2. Uma página de curso mostra capítulos e atividades.
3. Uma atividade renderiza (vídeo, documento, ou página dinâmica).
4. Um novo usuário pode se cadastrar e fazer login.
5. Um usuário conectado pode se matricular e ver o progresso atualizar.

Se seu agente conseguir marcar essas caixas contra sua instância real, você terminou.

<Callout type="warning">
Agentes são bons na estruturação e no caminho feliz, mas não conseguem ver os formatos
específicos do campo `content` da sua instância ou a configuração de armazenamento. Espere ter
que ajustá-lo no **visualizador de atividade** (as chaves dentro de `content` variam por
subtipo) e nas **URLs de mídia** (filesystem vs S3). A especificação aponta ambos como os locais
mais provavelmente precisando de ajuste.
</Callout>

## Por que uma especificação em vez de "me construa um LMS"?

Um prompt vago faz o agente inventar uma API. A
[especificação](/guides/build-learning-platform/agent-spec) fixa os endpoints **reais**, os
formatos de resposta, e a peculiaridade de autenticação/refresh — tudo extraído deste código —
então o agente constrói contra a API que realmente existe, não uma que ele alucinou. Essa é a
diferença entre um app que funciona e um app que retorna 404 em toda chamada.

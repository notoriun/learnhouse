# Webhooks

Webhooks permitem que o Notoriun **envie eventos para sua aplicação** no momento em que
acontecem — um aluno se matricula, conclui um curso, envia uma tarefa, se cadastra — para que
você possa reagir sem fazer polling. Use-os para sincronizar um CRM, enviar e-mails
customizados, atualizar um dashboard, ou disparar qualquer fluxo de trabalho.

<Callout type="info">
Webhooks são um recurso **Pro**. Eles são gerenciados por um usuário autenticado nas
configurações da organização ou na API de webhook abaixo.
</Callout>

## Como funciona

1. Você registra um **endpoint** (uma URL HTTPS pública) e escolhe quais eventos assinar.
2. Quando um evento assinado dispara, o Notoriun envia um `POST` para sua URL com um corpo JSON,
   **assinado** com um segredo por endpoint.
3. Seu receptor **verifica a assinatura**, depois trata o evento.
4. Se seu endpoint não retornar um `2xx`, o Notoriun **tenta novamente** — até 3 tentativas,
   esperando 1s depois 4s entre elas — e registra toda entrega.

## Gerenciando endpoints

Todos os endpoints de webhook vivem sob `/api/v1/orgs/{org_id}/webhooks`.

| Método | Caminho | Propósito |
| --- | --- | --- |
| `GET` | `/orgs/{org_id}/webhooks/events` | Lista todo tipo de evento e seu esquema de payload |
| `POST` | `/orgs/{org_id}/webhooks` | Cria um endpoint |
| `GET` | `/orgs/{org_id}/webhooks` | Lista seus endpoints |
| `GET` | `/orgs/{org_id}/webhooks/{webhook_uuid}` | Obtém um endpoint |
| `PUT` | `/orgs/{org_id}/webhooks/{webhook_uuid}` | Atualiza URL / eventos / estado ativo |
| `DELETE` | `/orgs/{org_id}/webhooks/{webhook_uuid}` | Exclui um endpoint |
| `POST` | `/orgs/{org_id}/webhooks/{webhook_uuid}/regenerate-secret` | Rotaciona o segredo de assinatura |
| `POST` | `/orgs/{org_id}/webhooks/{webhook_uuid}/test` | Envia um evento de teste `ping` |
| `GET` | `/orgs/{org_id}/webhooks/{webhook_uuid}/deliveries` | Logs de entrega recentes |

### Crie um endpoint

```bash
curl -X POST "http://localhost:1338/api/v1/orgs/1/webhooks" \
  -H "Authorization: Bearer <user_jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/api/webhooks/notoriun",
    "events": ["course_completed", "course_enrolled", "user_signed_up"]
  }'
```

A resposta contém o **segredo de assinatura exatamente uma vez** (com o prefixo `whsec_`).
Armazene-o — você vai precisar dele para verificar assinaturas, e ele não pode ser recuperado
novamente (só rotacionado). Ela também retorna os metadados usuais (`created_by_user_id`,
`creation_date`, …):

```json
{
  "webhook_uuid": "webhook_…",
  "url": "https://your-app.com/api/webhooks/notoriun",
  "events": ["course_completed", "course_enrolled", "user_signed_up"],
  "secret": "whsec_…store me…",
  "is_active": true
}
```

<Callout type="info">
Use `POST …/test` para enviar a si mesmo um evento `ping` enquanto constrói seu receptor, e
`GET …/deliveries` para inspecionar o que foi enviado e como seu endpoint respondeu.
</Callout>

## O payload

Toda entrega é um envelope JSON. O campo `data` é específico do evento:

```json
{
  "event": "course_completed",
  "delivery_id": "dlv_1a2b3c4d5e6f7081",
  "timestamp": "2026-06-22T12:00:00Z",
  "org_id": 1,
  "data": {
    "user": { "user_uuid": "user_…", "email": "learner@example.com", "username": "learner" },
    "course": { "course_uuid": "course_…", "name": "Introduction to Python" }
  }
}
```

Cada requisição também carrega estes headers:

| Header | Valor |
| --- | --- |
| `X-Webhook-Event` | O nome do evento, ex.: `course_completed` |
| `X-Webhook-Delivery` | Id de entrega único, ex.: `dlv_…` (use para idempotência) |
| `X-Webhook-Signature` | `sha256=<hmac-hex>` — HMAC-SHA256 do **corpo bruto da requisição** |
| `User-Agent` | `LearnHouse-Webhooks/1.0` |

## Verificando a assinatura

A assinatura é `sha256=` seguido do HMAC-SHA256 hex do **corpo bruto exato em bytes**, chaveado
pelo segredo do seu endpoint. Você deve calcular o HMAC sobre o corpo **não analisado** —
re-serializar o JSON vai mudar os bytes e quebrar a verificação.

Aqui está um receptor completo como um Route Handler do Next.js:

```ts filename="src/app/api/webhooks/notoriun/route.ts"
import { NextRequest, NextResponse } from 'next/server'
import crypto from 'node:crypto'

const SECRET = process.env.LEARNHOUSE_WEBHOOK_SECRET! // o valor whsec_…

export async function POST(req: NextRequest) {
  // 1. Leia o corpo BRUTO — não use req.json() primeiro.
  const raw = await req.text()
  const signature = req.headers.get('x-webhook-signature') ?? ''

  // 2. Recalcule o HMAC e compare em tempo constante.
  const expected =
    'sha256=' + crypto.createHmac('sha256', SECRET).update(raw).digest('hex')

  const valid =
    signature.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected))

  if (!valid) {
    return NextResponse.json({ error: 'invalid signature' }, { status: 401 })
  }

  // 3. Agora é seguro analisar e tratar.
  const payload = JSON.parse(raw)
  switch (payload.event) {
    case 'course_completed':
      console.log(`${payload.data.user.email} finished ${payload.data.course.name}`)
      // …envie um e-mail de certificado, atualize seu CRM, etc.
      break
    case 'user_signed_up':
      // …adicione à sua lista de e-mail
      break
  }

  // 4. Retorne 2xx rapidamente para que o Notoriun marque a entrega como bem-sucedida.
  return NextResponse.json({ received: true })
}
```

A mesma verificação em Node.js / Express puro:

```js
const crypto = require('node:crypto')

function verify(rawBody, signatureHeader, secret) {
  const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex')
  const a = Buffer.from(signatureHeader ?? '')
  const b = Buffer.from(expected)
  // timingSafeEqual lança erro se os tamanhos diferem, então proteja primeiro.
  return a.length === b.length && crypto.timingSafeEqual(a, b)
}
```

<Callout type="warning">
**Sempre verifique antes de confiar em um payload**, e trate as entregas como **pelo menos uma
vez** — o mesmo `delivery_id` pode chegar mais de uma vez depois de uma nova tentativa. Torne seu
handler idempotente (ex.: registre os `delivery_id`s já processados).
</Callout>

## Catálogo de eventos

Um webhook pode se inscrever em qualquer um destes eventos. O formato do campo `data` de cada
evento é retornado em tempo real por `GET /api/v1/orgs/{org_id}/webhooks/events`, então sua
ferramenta nunca precisa fixá-lo no código.

| Categoria | Eventos |
| --- | --- |
| **Sistema** | `ping` |
| **Progresso de Aprendizado** | `course_completed`, `course_enrolled`, `activity_completed`, `assignment_submitted`, `assignment_graded`, `certificate_claimed` |
| **Usuário e Acesso** | `user_signed_up`, `user_email_verified`, `user_role_changed`, `user_invited_to_org`, `user_removed_from_org` |
| **Ciclo de Vida do Curso** | `course_created`, `course_published`, `course_deleted`, `course_update_published` |
| **Gestão de Conteúdo** | `activity_version_created`, `activity_version_restored`, `course_contributor_added`, `course_contributor_removed`, `collection_created`, `podcast_episode_created` |
| **Colaboração** | `board_created`, `board_member_added`, `playground_created` |
| **Comunidade** | `discussion_posted`, `comment_created`, `discussion_pinned`, `discussion_locked`, `discussion_vote_cast` |
| **Grupos** | `usergroup_created`, `usergroup_deleted`, `usergroup_users_added`, `usergroup_resources_added` |
| **Assinaturas** | `pack_activated`, `pack_deactivated` |
| **Organização** | `org_signup_method_changed`, `org_ai_config_changed`, `org_payments_config_changed` |

## Notas de segurança

- **Segredos** são armazenados criptografados em repouso e mostrados a você só na criação e na
  rotação.
- **Assinaturas** usam HMAC-SHA256 sobre o corpo bruto — a mesma convenção do GitHub e do
  Stripe.
- **Requisições de saída são protegidas contra SSRF**: o Notoriun valida a URL de destino e o IP
  resolvido antes de toda entrega, então os endpoints precisam ser publicamente alcançáveis —
  `localhost` e faixas de IP privadas/reservadas são sempre rejeitados (em todo ambiente).

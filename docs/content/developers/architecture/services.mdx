# Serviços de Apoio

O Notoriun depende de vários serviços de apoio que rodam junto com as aplicações principais.

- No **desenvolvimento** (`learnhouse dev`), o PostgreSQL e o Redis rodam em Docker via
  `.learnhouse/docker-compose.dev.yml`, enquanto os processos de API, web e collab rodam
  localmente no host.
- Em **produção self-hosted**, a CLI do Notoriun gera um `docker-compose.yml` a partir de
  templates em `apps/cli/src/templates/` que executa PostgreSQL, Redis, um único contêiner
  `learnhouse-app` (que empacota web + API + collab), e nginx ou Caddy como proxy reverso.

## PostgreSQL

`pgvector/pgvector:pg16` (PostgreSQL 16 com a extensão pgvector) é o banco de dados principal do
Notoriun. Ele armazena todos os dados persistentes da aplicação, incluindo:

- Organizações e suas configurações
- Contas de usuário e registros de autenticação
- Cursos, capítulos e atividades
- Coleções, trilhas e rastreamento de progresso
- Embeddings vetoriais de IA (via a extensão pgvector)

O backend se conecta ao PostgreSQL através do SQLModel.

**Porta padrão:** `5432`

## Redis

O Redis serve como a camada de cache, gestão de sessão e persistência de colaboração:

- **Cache** -- Reduz a carga no banco de dados armazenando dados acessados frequentemente em
  memória.
- **Armazenamento de sessão** -- Gerencia dados de sessão de usuário para acesso rápido.
- **Estado de colaboração** -- Armazena o estado de documento Yjs do servidor Collab com um TTL
  de 1 hora antes de ser persistido no PostgreSQL.
- **Pub/Sub** -- Permite comunicação entre serviços quando necessário.

O compose de dev usa `redis:8.6.1-alpine`; o compose de produção self-host gerado pela CLI usa
`redis:7.2.3-alpine`.

**Porta padrão:** `6379`

## Hocuspocus (Servidor de Colaboração)

O servidor Hocuspocus, localizado em `apps/collab`, fornece capacidades de edição colaborativa em
tempo real. É uma aplicação Node.js + TypeScript (executada via `tsx` em dev) construída sobre o
[Hocuspocus](https://hocuspocus.dev/) `^3.0.0`, que usa a biblioteca CRDT Yjs por baixo dos
panos. Ele se conecta ao Redis via `ioredis ^5.9.3`.

**Porta padrão:** `4000` (configurável via a variável de ambiente `COLLAB_PORT`)

### Autenticação

O servidor Collab realiza verificação JWT usando o mesmo segredo do backend da API. Na conexão,
ele verifica a participação no quadro fazendo uma requisição à API.

### Persistência

O estado do documento segue uma estratégia de persistência em duas camadas:

1. **Redis** -- O estado Yjs é primeiro armazenado no Redis com um TTL de 1 hora
   (`REDIS_YDOC_TTL = 3600`) para acesso rápido.
2. **PostgreSQL** -- O estado é persistido no banco de dados via a API com um debounce de 5
   segundos (`DB_FLUSH_DELAY = 5000`) para evitar escritas excessivas.

### Limite de Taxa e Capacidade

- **Máximo de 10 usuários simultâneos** por quadro (`MAX_BOARD_USERS`)
- **Limite de taxa** de 30 conexões por IP por minuto (`RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_MS`)

### Recursos Principais

- **Sincronização de documento em tempo real** -- Vários usuários podem editar o mesmo quadro
  simultaneamente.
- **Resolução de conflitos** -- Os CRDTs do Yjs lidam com edições concorrentes sem conflitos.
- **Persistência durável** -- O estado do documento sobrevive a reinícios do servidor através do
  Redis e do PostgreSQL.

O frontend se conecta ao Hocuspocus diretamente via WebSocket usando o cliente
`@hocuspocus/provider` para edição colaborativa de baixa latência.

## Proxy Reverso (nginx ou Caddy)

A stack self-host gerada pela CLI usa um dos dois proxies reversos, dependendo da escolha de SSL
feita durante a instalação:

- **Caddy** (`caddy:2-alpine`) — selecionado quando "SSL Automático" está ativado; lida com a
  emissão e renovação de certificados Let's Encrypt automaticamente.
- **nginx** (`nginx:alpine`) — selecionado para SSL manual ou configurações somente HTTP.

Ambos roteiam o tráfego para o único contêiner `learnhouse-app`, que internamente serve o
frontend Next.js, o backend FastAPI e o servidor de colaboração Hocuspocus.

## Comunicação entre Serviços

Logicamente, uma requisição flui assim:

```
Client
  └── nginx / caddy (proxy reverso)
        └── learnhouse-app (contêiner único)
              ├── Next.js (web)
              ├── FastAPI (api)
              │     ├── PostgreSQL (porta 5432)
              │     └── Redis (porta 6379)
              └── Hocuspocus (collab)
                    ├── Redis (porta 6379)
                    └── FastAPI (para persistência e autenticação baseada em JWT)
```

O servidor Hocuspocus autentica conexões via JWT (segredo compartilhado com a API), verifica a
participação no quadro através da API, e persiste o estado do documento tanto no Redis quanto no
PostgreSQL (via a API). O PostgreSQL é acessado diretamente apenas pelo backend.

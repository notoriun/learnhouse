# Autenticação da API

A API do Notoriun suporta **cookies JWT** para sessões de navegador e **tokens de API** para
acesso programático.

## Autenticação JWT

O endpoint de login aceita dados `application/x-www-form-urlencoded` com os campos `username` (o
e-mail do usuário) e `password`, e retorna um token de acesso JWT (HS256, expira em 8 horas):

```bash
curl -X POST http://localhost:1338/api/v1/auth/login \
  -F 'username=you@example.com' \
  -F 'password=your-password'
```

Depois autentique requisições via o cabeçalho `Authorization`:

```bash
curl http://localhost:1338/api/v1/users/profile \
  -H "Authorization: Bearer <access_token>"
```

O token também é definido como um `access_token_cookie` para sessões baseadas em navegador. Use
`GET /api/v1/auth/refresh` para renovar tokens expirados dentro da janela de refresh de 30 dias.

<Callout type="info">
Logins têm limite de taxa por IP, e tentativas falhas repetidas bloqueiam temporariamente a conta.
Implantações SaaS também exigem `email_verified=true` antes que o login seja bem-sucedido.
</Callout>

## Tokens de API

<Callout type="info">
Tokens de API estão disponíveis no **plano Pro**. Crie e gerencie-os nas configurações da
organização.
</Callout>

Para acesso programático, use tokens de API (com o prefixo `lh_`):

```bash
curl http://localhost:1338/api/v1/users/profile \
  -H "Authorization: Bearer lh_your_api_token_here"
```

## Endpoints de Autenticação

| Método | Endpoint | Descrição |
| --- | --- | --- |
| `POST` | `/api/v1/auth/login` | Login com `username` + `password` codificados em formulário |
| `GET` | `/api/v1/auth/refresh` | Renova um token expirado |
| `DELETE` | `/api/v1/auth/logout` | Invalida a sessão |
| `POST` | `/api/v1/auth/oauth` | Login via Google OAuth |
| `POST` | `/api/v1/auth/verify-email` | Verifica o endereço de e-mail |
| `POST` | `/api/v1/auth/resend-verification` | Reenvia um e-mail de verificação |

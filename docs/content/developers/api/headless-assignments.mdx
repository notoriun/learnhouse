# Tarefas Headless

As tarefas do Notoriun podem ser inteiramente conduzidas a partir do seu próprio frontend. Com um
token de API você pode criar tarefas e atividades, armazenar um objeto de dados customizado
arbitrário em cada atividade, ler envios e notas, enviar respostas em nome dos seus alunos, e
corrigi-las — tudo pela API REST padrão, sem precisar da interface do Notoriun.

<Callout type="info">
Tokens de API estão disponíveis no **plano Pro**. Crie um em **Configurações da Organização →
Acesso à API** e conceda a ele a permissão **Assignments**. Tokens têm o prefixo `lh_` e são
restritos a uma única organização.
</Callout>

## Permissões

O acesso a tarefas é controlado por um único bucket de permissões `assignments` no token. As
quatro ações mapeiam para capacidades assim:

| Ação | O que permite |
| --- | --- |
| `create` | Criar tarefas e atividades (incluindo o objeto de dados customizado `contents`), enviar arquivos de referência, e enviar respostas em nome dos alunos |
| `read` | Ler tarefas, atividades, envios e notas calculadas |
| `update` | Atualizar tarefas e atividades, e corrigir envios (definir nota, feedback e status) |
| `delete` | Excluir tarefas e atividades |

Conceda apenas o que sua integração precisa — um painel somente leitura quer `read`; um bot de
correção quer `read` + `update`; um frontend de tarefas totalmente customizado quer `create` +
`read` + `update`.

Todas as requisições são restritas à organização do token: tentar acessar uma tarefa em outra
organização retorna `403`.

```bash
curl http://localhost:1338/api/v1/assignments/{assignment_uuid} \
  -H "Authorization: Bearer lh_your_api_token_here"
```

## Criação

Estes endpoints criam e gerenciam tarefas e suas atividades. Uma tarefa é vinculada a uma
atividade de curso, então você fornece `org_id`, `course_id`, `chapter_id`, e `activity_id` ao
criar uma.

| Método | Endpoint | Ação |
| --- | --- | --- |
| `POST` | `/api/v1/assignments/` | `create` |
| `GET` | `/api/v1/assignments/{assignment_uuid}` | `read` |
| `GET` | `/api/v1/assignments/activity/{activity_uuid}` | `read` |
| `GET` | `/api/v1/assignments/course/{course_uuid}` | `read` |
| `PUT` | `/api/v1/assignments/{assignment_uuid}` | `update` |
| `DELETE` | `/api/v1/assignments/{assignment_uuid}` | `delete` |
| `POST` | `/api/v1/assignments/{assignment_uuid}/tasks` | `create` |
| `GET` | `/api/v1/assignments/{assignment_uuid}/tasks` | `read` |
| `GET` | `/api/v1/assignments/task/{assignment_task_uuid}` | `read` |
| `PUT` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}` | `update` |
| `DELETE` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}` | `delete` |
| `POST` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}/ref_file` | `create` |

```bash
curl -X POST http://localhost:1338/api/v1/assignments/ \
  -H "Authorization: Bearer lh_your_api_token_here" \
  -H "Content-Type: application/json" \
  -d '{
        "title": "Field Report",
        "description": "Submit your findings",
        "due_date": "2030-01-01",
        "grading_type": "NUMERIC",
        "org_id": 1,
        "course_id": 12,
        "chapter_id": 34,
        "activity_id": 56
      }'
```

## Atividades customizadas — traga seu próprio objeto de dados

Cada atividade tem um `assignment_type` e um objeto JSON livre `contents`. Para uma tarefa
totalmente customizada, use o tipo `CUSTOM`: o Notoriun armazena seu `contents` (a definição da
atividade) e a resposta do aluno `task_submission` como um objeto JSON arbitrário, de propriedade
de quem chama a API. O servidor nunca o interpreta ou corrige automaticamente — é seu para
renderizar e corrigir como quiser.

```bash
curl -X POST http://localhost:1338/api/v1/assignments/{assignment_uuid}/tasks \
  -H "Authorization: Bearer lh_your_api_token_here" \
  -H "Content-Type: application/json" \
  -d '{
        "title": "Interactive Map Challenge",
        "description": "Place the pins",
        "assignment_type": "CUSTOM",
        "max_grade_value": 100,
        "contents": {
          "widget": "interactive-map",
          "config": { "regions": ["north", "south"], "maxPins": 7 },
          "rubric": [ { "id": "r1", "label": "Accuracy", "points": 80 } ]
        }
      }'
```

O `contents` que você recebe de volta em `GET /assignments/task/{uuid}` é byte a byte o que você
armazenou.

<Callout type="info">
Os tipos de atividade integrados — `QUIZ`, `FORM`, `CODE`, `SHORT_ANSWER`, `NUMBER_ANSWER` — são
corrigidos automaticamente pelo Notoriun com base no esquema do `contents`. `CUSTOM` (e
`FILE_SUBMISSION`) **não** são corrigidos automaticamente e são corrigidos manualmente.
</Callout>

## Envios e correção

Os alunos são referenciados pelo `user_id` existente no Notoriun. Estes endpoints permitem ler
envios, escrever a resposta de um aluno em seu nome, e finalizar notas.

| Método | Endpoint | Ação |
| --- | --- | --- |
| `GET` | `/api/v1/assignments/{assignment_uuid}/submissions` | `read` |
| `GET` | `/api/v1/assignments/{assignment_uuid}/submissions/{user_id}` | `read` |
| `GET` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}/submissions` | `read` |
| `GET` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}/submissions/user/{user_id}` | `read` |
| `PUT` | `/api/v1/assignments/{assignment_uuid}/tasks/{assignment_task_uuid}/submissions` | `create` (envio em nome de) |
| `POST` | `/api/v1/assignments/{assignment_uuid}/submissions` | `create` (envio em nome de) |
| `GET` | `/api/v1/assignments/{assignment_uuid}/submissions/{user_id}/grade` | `read` |
| `POST` | `/api/v1/assignments/{assignment_uuid}/submissions/{user_id}/grade` | `update` |
| `PUT` | `/api/v1/assignments/{assignment_uuid}/submissions/{user_id}` | `update` |

### Enviando em nome de um aluno

Para escrever a resposta de um aluno, passe o id dele no Notoriun como `on_behalf_of_user_id`. O
aluno já deve ser membro da organização do token.

```bash
# Salva a resposta de um aluno para uma atividade
curl -X PUT "http://localhost:1338/api/v1/assignments/{assignment_uuid}/tasks/{task_uuid}/submissions?on_behalf_of_user_id=42" \
  -H "Authorization: Bearer lh_your_api_token_here" \
  -H "Content-Type: application/json" \
  -d '{ "task_submission": { "answer": "my custom answer" } }'

# Marca a tarefa como enviada para esse aluno
curl -X POST "http://localhost:1338/api/v1/assignments/{assignment_uuid}/submissions?on_behalf_of_user_id=42" \
  -H "Authorization: Bearer lh_your_api_token_here"
```

### Correção

Duas formas de corrigir, ambas restritas por `update`:

- `POST .../submissions/{user_id}/grade` recalcula a nota a partir dos envios de atividade
  (tipos auto-corrigíveis são re-verificados no servidor) e aceita um `overall_feedback` opcional
  no corpo.
- `PUT .../submissions/{user_id}` define a nota, status e feedback diretamente — útil para
  atividades customizadas que você mesmo corrigiu.

```bash
curl -X POST http://localhost:1338/api/v1/assignments/{assignment_uuid}/submissions/42/grade \
  -H "Authorization: Bearer lh_your_api_token_here" \
  -H "Content-Type: application/json" \
  -d '{ "overall_feedback": "Great work" }'
```

<Callout type="info">
Alguns endpoints de envio são **exclusivos de sessão** e não podem ser chamados com um token: as
leituras "meu próprio envio" voltadas ao aluno (`.../submissions/me`), o endpoint de retry, e o
endpoint "marcar atividade como concluída". Um token sempre age sobre um `user_id` explícito, em
vez de um "eu" implícito.
</Callout>

## Exemplo de ponta a ponta

Um frontend customizado pode executar todo o ciclo de vida com um único token (`create` + `read`
+ `update`):

1. `POST /assignments/` — cria a tarefa em uma atividade de curso.
2. `POST /assignments/{uuid}/tasks` — adiciona uma atividade `CUSTOM` com seu objeto de dados.
3. `PUT  /assignments/{uuid}/tasks/{task}/submissions?on_behalf_of_user_id=42` — armazena a
   resposta de um aluno.
4. `POST /assignments/{uuid}/submissions?on_behalf_of_user_id=42` — marca como enviada.
5. `PUT  /assignments/{uuid}/submissions/42` — define a nota e o feedback.

Veja [Autenticação](/developers/api/authentication) para saber como criar e usar tokens de API, e
o [guia de tarefas da plataforma](/platform/assignments) para o fluxo dentro do app.

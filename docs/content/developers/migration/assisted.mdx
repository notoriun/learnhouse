# Migração Assistida por IA

O Notoriun expõe uma API de três chamadas que envia uma pasta de arquivos de mídia, pede ao
Gemini para organizá-los em capítulos e atividades, e depois cria o curso inteiro em uma única
transação. Este é o caminho certo quando você tem um diretório repleto de gravações de aula
antigas, PDFs, e imagens, mas nenhuma estrutura existente.

Todos os três endpoints vivem sob `/api/v1/courses/migrate/`. Eles exigem uma **sessão de
usuário autenticada (JWT)** com permissão para criar cursos na organização de destino.

<Callout type="warning">
**Tokens de API são bloqueados aqui.** Diferente dos endpoints padrão de curso/capítulo/
atividade, os endpoints de migração rejeitam requisições autenticadas com um token de API
`lh_*` (`HTTP 403: API tokens cannot access this resource. Only user authentication is allowed.`).
Se você só tem um token de API, use a **troca de token pelo admin** para gerar um JWT primeiro:

```bash
JWT=$(curl -s -X POST 'http://localhost:1338/api/v1/admin/{org_slug}/auth/token' \
  -H 'Authorization: Bearer lh_your_api_token' \
  -H 'Content-Type: application/json' \
  -d '{"user_id": 1}' | jq -r .access_token)

# Agora use $JWT para as chamadas migrate/*
curl -X POST "http://localhost:1338/api/v1/courses/migrate/upload?org_id=1" \
  -H "Authorization: Bearer $JWT" -F 'files=@./video.mp4'
```

O endpoint de troca de token exige que o token de API tenha a permissão `users.action_read` e
que o usuário alvo pertença à mesma organização.
</Callout>

## Quando usar isso vs. migração programática

| Situação | Use |
| --- | --- |
| Você tem uma exportação limpa de outro LMS com um layout conhecido de capítulo / atividade | [Migração Programática](/developers/migration/programmatic) |
| Você precisa que todo detalhe da árvore resultante seja exato (títulos, ordenação, tipos) | Programática |
| Você tem uma pilha de arquivos e quer que o Notoriun proponha uma estrutura | Assistida por IA (esta página) |
| Você quer criar páginas dinâmicas de texto rico | Programática (a assistida produz atividades só de mídia) |

<Callout type="warning">
O fluxo assistido só lida com **arquivos de mídia** -- vídeo, PDF, imagem e áudio. Ele não
importa HTML, Markdown, ou conteúdo de texto rico para páginas dinâmicas. Para migrações com
muito texto, escreva um script programático.
</Callout>

## Tipos de arquivo suportados

| Extensão | Atividade resultante | Subtipo |
| --- | --- | --- |
| `mp4`, `webm`, `mov` | `TYPE_VIDEO` | `SUBTYPE_VIDEO_HOSTED` |
| `pdf` | `TYPE_DOCUMENT` | `SUBTYPE_DOCUMENT_PDF` |
| `png`, `jpg`, `jpeg`, `webp` | `TYPE_DYNAMIC` (bloco de imagem) | `SUBTYPE_DYNAMIC_PAGE` |
| `mp3`, `wav` | `TYPE_DYNAMIC` (bloco de áudio) | `SUBTYPE_DYNAMIC_PAGE` |

Arquivos com qualquer outra extensão são ignorados. O limite de tamanho por arquivo é **5 GB**,
e o tamanho total de upload por migração é **20 GB**.

## Visão geral dos endpoints

| # | Método | Caminho | Propósito |
| --- | --- | --- | --- |
| 1 | `POST` | `/api/v1/courses/migrate/upload?org_id={org_id}` | Envia um ou mais arquivos para uma área de retenção temporária. Retorna um `temp_id`. |
| 2 | `POST` | `/api/v1/courses/migrate/suggest?org_id={org_id}` | Pede ao Gemini para propor uma árvore de curso a partir dos arquivos enviados. Retorna a estrutura para você revisar. |
| 3 | `POST` | `/api/v1/courses/migrate/create?org_id={org_id}` | Confirma a estrutura (possivelmente editada): cria o curso, capítulos, atividades, e envia cada arquivo ao seu destino final. |

Uploads temporários com mais de 60 minutos são coletados automaticamente pelo garbage
collector, então conclua uma migração em uma única sessão.

## Passo 1 -- Envie os arquivos

Envie até 20 GB de arquivos em uma ou mais requisições. Passe `temp_id` em requisições
subsequentes para anexar ao mesmo pacote de migração:

```bash
# Primeiro lote -- cria um novo temp_id
curl -X POST "http://localhost:1338/api/v1/courses/migrate/upload?org_id=1" \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'files=@./lectures/lesson-01.mp4' \
  -F 'files=@./lectures/lesson-02.mp4' \
  -F 'files=@./handouts/syllabus.pdf'
```

Resposta:

```json
{
  "temp_id": "9c4e3...-d8f1-4...",
  "files": [
    {
      "file_id": "f1a2b3...",
      "filename": "lesson-01.mp4",
      "file_type": "video/mp4",
      "size": 41943040,
      "extension": "mp4"
    },
    ...
  ],
  "skipped": []
}
```

Anexe mais arquivos ao mesmo `temp_id`:

```bash
curl -X POST "http://localhost:1338/api/v1/courses/migrate/upload?org_id=1&temp_id=9c4e3...-d8f1-4..." \
  -H "Authorization: Bearer lh_your_api_token" \
  -F 'files=@./images/diagram-01.png'
```

`skipped` lista arquivos rejeitados por extensão não suportada ou tamanho. Eles não contam para
o total, mas você deve reencodar e reenviar se precisar deles.

<Callout type="info">
O servidor limita uploads simultâneos a **3 requisições simultâneas por processo**. Se você
paralelizar o upload de um pacote grande, ajuste seu ritmo de acordo.
</Callout>

## Passo 2 -- Peça uma estrutura sugerida

Envie o `temp_id` e um nome de curso; o Gemini agrupa os arquivos em capítulos e propõe títulos
de atividade:

```bash
curl -X POST "http://localhost:1338/api/v1/courses/migrate/suggest?org_id=1" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "temp_id": "9c4e3...-d8f1-4...",
    "course_name": "Introduction to Astronomy",
    "description": "Self-paced intro to astronomy concepts."
  }'
```

Resposta:

```json
{
  "course_name": "Introduction to Astronomy",
  "course_description": "Self-paced intro to astronomy concepts.",
  "chapters": [
    {
      "name": "Foundations",
      "activities": [
        {
          "name": "Course syllabus",
          "activity_type": "TYPE_DOCUMENT",
          "activity_sub_type": "SUBTYPE_DOCUMENT_PDF",
          "file_ids": ["f3c4d5..."]
        },
        {
          "name": "Lecture 1 -- The night sky",
          "activity_type": "TYPE_VIDEO",
          "activity_sub_type": "SUBTYPE_VIDEO_HOSTED",
          "file_ids": ["f1a2b3..."]
        }
      ]
    },
    {
      "name": "The solar system",
      "activities": [...]
    }
  ]
}
```

O prompt de IA é parametrizado pelas extensões de arquivo (veja a tabela no topo desta página),
então os tipos sugeridos são determinísticos por extensão; só os **nomes**, o **agrupamento de
capítulo**, e a **ordenação** são gerados por IA.

Se a chamada de IA falhar ou a cota se esgotar, o endpoint recorre a uma **estrutura plana** --
um único capítulo chamado "Content" contendo uma atividade por arquivo, com nomes derivados dos
nomes de arquivo. Isso garante que você ainda consiga concluir a migração mesmo se o serviço de
IA estiver degradado.

### Editando a sugestão

A estrutura é apenas JSON -- modifique-a no seu cliente como quiser antes de enviá-la ao passo
3. Edições comuns:

- Renomear capítulos e atividades
- Mover atividades entre capítulos (mover uma entrada de `file_ids` entre atividades, ou
  duplicar o objeto de atividade)
- Dividir ou mesclar capítulos
- Reordenar atividades (a ordem no array se torna a ordem da atividade)
- Descartar uma atividade removendo-a do array (seu arquivo simplesmente não será importado)

As únicas restrições são que todo `file_id` que você referenciar deve existir no manifesto, todo
`activity_type` / `activity_sub_type` deve ser um valor de enum válido, e todo arquivo deve ser
referenciado por **no máximo uma atividade** (referenciar o mesmo arquivo duas vezes vai falhar
na segunda cópia).

## Passo 3 -- Crie o curso

Envie a estrutura (possivelmente editada) de volta com o mesmo `temp_id`. O servidor cria o
curso, capítulos, atividades, e copia cada arquivo da área de upload temporária para seu local
final -- tudo em uma única transação de banco de dados:

```bash
curl -X POST "http://localhost:1338/api/v1/courses/migrate/create?org_id=1" \
  -H "Authorization: Bearer lh_your_api_token" \
  -H "Content-Type: application/json" \
  -d '{
    "temp_id": "9c4e3...-d8f1-4...",
    "structure": {
      "course_name": "Introduction to Astronomy",
      "course_description": "Self-paced intro to astronomy concepts.",
      "chapters": [
        {
          "name": "Foundations",
          "activities": [
            {
              "name": "Course syllabus",
              "activity_type": "TYPE_DOCUMENT",
              "activity_sub_type": "SUBTYPE_DOCUMENT_PDF",
              "file_ids": ["f3c4d5..."]
            }
          ]
        }
      ]
    }
  }'
```

Resposta:

```json
{
  "course_uuid": "course_b7e1...",
  "course_name": "Introduction to Astronomy",
  "chapters_created": 3,
  "activities_created": 12,
  "success": true,
  "error": null
}
```

O curso criado é **não publicado e privado** por padrão (`public: false`, `published: false`).
Visite `/{org_slug}/courses/{course_uuid}/edit` no painel para revisar e publicá-lo, ou use
`PUT /api/v1/courses/{course_uuid}` para publicar programaticamente.

Se algo falhar (erro de banco de dados, falha na cópia de arquivo, arquivos ausentes), a
transação inteira é revertida e `success` é `false` com o erro em `error`. O diretório de
upload temporário é limpo de qualquer forma -- comece de novo a partir do passo 1 com um upload
novo.

## Script de ponta a ponta (bash)

```bash
#!/usr/bin/env bash
set -euo pipefail

API=http://localhost:1338/api/v1
API_TOKEN=lh_your_api_token        # token de API do plano Pro
ORG_SLUG=default
ORG_ID=1
USER_ID=1                          # o usuário a agir como
COURSE_NAME="Migrated content"

# 0. Troca o token de API por um JWT de usuário (endpoints migrate/* rejeitam tokens de API)
TOKEN=$(curl -fsS -X POST "$API/admin/$ORG_SLUG/auth/token" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"user_id\":$USER_ID}" | jq -r .access_token)

# 1. Envia tudo em ./content/
UPLOAD_RESP=$(curl -fsS -X POST "$API/courses/migrate/upload?org_id=$ORG_ID" \
  -H "Authorization: Bearer $TOKEN" \
  $(for f in ./content/*; do echo -n "-F files=@$f "; done))
TEMP_ID=$(echo "$UPLOAD_RESP" | jq -r '.temp_id')

# 2. Sugere a estrutura
STRUCTURE=$(curl -fsS -X POST "$API/courses/migrate/suggest?org_id=$ORG_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"temp_id\":\"$TEMP_ID\",\"course_name\":\"$COURSE_NAME\"}")

# 3. (Opcional) Edite a estrutura aqui, ex. com `jq` -- omitido neste exemplo.

# 4. Cria o curso
curl -fsS -X POST "$API/courses/migrate/create?org_id=$ORG_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"temp_id\":\"$TEMP_ID\",\"structure\":$STRUCTURE}"
```

## Limpando

Se você abandonar uma migração no meio do caminho, o diretório temporário é excluído
automaticamente depois de 60 minutos pela tarefa de limpeza periódica. Não há endpoint público
para excluir um `temp_id` antecipadamente -- se você precisar tentar novamente imediatamente,
basta iniciar um novo upload (você receberá um novo `temp_id`).

Uma migração concluída com sucesso não deixa estado temporário: o passo 3 exclui o diretório
temporário assim que a transação é confirmada.

## Limitações

- **Só mídia.** Conteúdo de texto (Markdown, HTML, texto rico) não é importado. As atividades
  de página dinâmica criadas a partir de imagens e áudio contêm um único bloco referenciando o
  arquivo; nenhuma prosa ao redor é gerada.
- **Fallback de capítulo único.** Se o Gemini estiver indisponível, todo arquivo cai em um
  único capítulo chamado "Content". Você pode editar a estrutura antes do passo 3 para
  reorganizar.
- **Sem tarefas / quizzes / SCORM.** O fluxo não infere conteúdo interativo a partir de mídia.
  Crie-os separadamente via o fluxo programático.
- **Um arquivo por atividade.** Cada atividade migrada referencia exatamente um arquivo de
  origem. Se você precisar de uma atividade que combine vários arquivos (ex.: uma página
  dinâmica com várias imagens), construa isso com o fluxo programático.

Para qualquer coisa além dos limites acima, recorra à
[Migração Programática](/developers/migration/programmatic) -- você também pode usar o fluxo
assistido para o grosso da mídia e continuar com chamadas programáticas para adicionar páginas
de texto rico, tarefas, e quizzes.
